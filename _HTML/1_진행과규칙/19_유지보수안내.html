3. 전투 계산 구조

프레임 순서

  • BattleEntry.Update: dt = min(Time.deltaTime, 1/20) × 배속 → sim.BeginFrame(dt) → 끝났으면 결과, 아니면 sim.Schedule(dt, Time.time). 일시정지·쉬움에서 지도 열림이면 시간 멈춤
  • BattleEntry.LateUpdate: sim.Complete() → view.ApplyAtmosphere → view.Draw
  • BeginFrame(메인 스레드, 작업이 끝난 뒤): 미뤄 둔 명령 → 날씨 → 성벽·병사 피해 반영(KillSoldiersFromDamage) → 등장(Spawn) → 전령 → 묶음 이동 → 총안 걸음 → 우회 → 마법사 → 마법 → 함정 → 승패

작업(Job) — Combat/Battle/BattleJobs.cs, 모두 Burst, BattleSim.Schedule 순서

  • EnemyStepJob 적 이동·등반 → (지형이 있으면) TerrainHitJob → SideTallyJob 면별 집계
  • BattleAssignCellsJob → BattleBuildGridJob 4m 공간 격자
  • SoldierFireJob 병사 사격(표적 고르기, 대포 불붙이기)
  • AllocateShotsJob 투사체 풀 → MoveShotsJob 이동·착지 → ApplyBattleHitsJob 피해·사망(세대값으로 한 번만)
  • WriteBattleEnemyInstancesJob, WriteShotInstancesJob 그리기 데이터

배열·분대·묶음 (BattleSim.cs, 모두 NativeArray)

  • 적: ePos, eVel, eState, eClimb, eSide, eSpeed, eStop, eKind, eHp, eMaxHp, eGen, eIncoming, eAnim, eGroup — 같은 종류끼리 이어 붙여 종류마다 한 번에 그린다(enemyGroups). 적 상태는 EnemyState(Waiting·Walking·AtWall·Climbing·OnWall·Dead), 죽은 슬롯은 다시 쓰지 않는다
  • 병사: sPos, sAlive, sWeapon, sCooldown, sSide, sAway, … + 부분 파일의 sAim, sHasAim, sIdle, sCannonReach, sFireTime, sFuse, sPendingShot. 병종끼리 이어 붙임(soldierGroups). 대포 분대는 맨 앞 병사만 무기(나머지 sWeapon = -1), 병사는 뒤에서부터 잃는다
  • 분대: SquadInfo(State·Side·FirstSoldier·Alive·Start·Movable·UnitName·SoldierHp). 10명 묶음으로 나눈다(BattleSim.Groups.cs GroupSize = 10, 대포 분대는 한 묶음). 결과(BuildResult)에서 원래 분대별로 다시 더한다
  • 투사체 풀: shotCapacity = Clamp(병사 수 × 4, 1024, 65536)

    • codex-send.ps1 -Message <글>: 돌고 있는 Codex 대화에 메시지를 넣는다.
  • 카드 폴더에서는 유니티를 열지 않는다. 카드 가지 안의 커밋은 10.3 허락이 필요 없다. 결과는 CARD_RESULT.md(커밋하지 않음).
  • 합치기는 스크립트가 없다. 메인 폴더에서 조정 담당이 하나씩 git merge --no-ff card/<카드>로 합치고(10.3 순서), 합칠 때마다 빠른 컴파일 확인을 한다. 전체 시험은 밤 시험으로 돌린다. 끝난 카드는 폴더와 가지를 정리한다.
  • 이 셸 환경에는 PATH에 git이 없다. C:\Users\User\.cache\codex-runtimes\codex-primary-runtime\dependencies\native\git\cmd\git.exe를 쓴다.

7. 그림 넣는 법

순서 (D-064, D-074)

  • Claude가 Codex에게 목적·화면·규격을 보낸다.
  • Codex가 Docs/References/codex_<주제>_v<N>/(또는 codex_k0NN_v1/)에 시안을 만든다: README·manifest(크기·기준점·해시)·원안·검토 그림. 사용자용 검토 페이지는 _HTML/<분류>/codex_K-0NN_<주제>_v1.html.
  • 사용자가 확정한다.
  • Claude가 게임에 연결한다: 그림을 Art/ 아래로 복사하고, .meta를 두고, 정의 에셋 필드에 연결한다.
  • 게임 안 캡처로 시안과 비교한다: 모양·크기·방향·도트 밀도·가독성·가림.
    • 사용자 확정 전에 미리 연결하는 일도 있다("미리 연결, 사용자 검토 전" 주석). 바꿔 끼울 때는 에셋의 그림 연결 한 줄만 고치면 된다.

캐릭터 시트 규격 (Combat/PerfLab/PerfLabArt.cs)

  • 한 칸 256×384, 발 기준점 (128, 352)(위에서 352px). 그림 크기로 열·행을 센다(FromSheet). 칸 번호는 왼쪽 위부터 행 × 열 수 + 열이고, 음수면 좌우 뒤집기다.
  • 칸 안의 인물 키가 시트마다 달라도 같은 크기로 보이게 한다: SheetScale = 기준 384 / 그림 인물 키. 인물 키 표는 Tools/SheetMeasure/measure-sheets.ps1이 PerfLabSheetHeights.cs로 다시 만든다. 새 시트를 넣으면 이 도구를 다시 돌린다.
  • 주인공 4×4(행: 0 뒷모습 걷기 · 1 옆 걷기 · 2 옆 달리기 · 3 앞), 고블린 4×2(걷기·공격)
  • 동작 시트는 같은 개체 버퍼에서 칸 구간으로 나눠 그린다(셰이더 _FrameWindow): 원래 0~15, 공격 16, 세우기 32, 오르기 48, 사격 64, 불붙이기 80, 쓰러짐 96
  • 투사체 1칸 256×128(가운데 기준, +X = 앞), 사다리 256×1536(아래 1472, 실체 1152px = 4.3m)
  • 노멀맵은 짝 시트와 같은 칸 배치로 둔다. 초록이 위, 가져오기 종류는 노멀맵(sRGB 끔).

어디에 두나

  • 정의에 연결하는 시트는 Art/Characters/{Static,Walk,Run,Fire,Fall,Goblin,Hero,Ladder,Projectiles}에 두고 UnitDef·EnemyDef 필드로 연결한다.
    • UnitDef: sheet, idle/run, normal, fire, death, cast, command, projectile, ignite
    • EnemyDef: sheet, normal, attack, death, deploy, climb, ladder
    • 정의는 Data/Combat/Units·Enemies/*.asset에서 guid로 가리킨다.
  • 이름으로 읽는 그림은 Resources 아래에 둔다: Art/Battle/Resources/BattleArt/(Cannon·Effects·Props·Sky·Terrain·World), Art/UI/Resources/{HudArt,ScreenArt,TrapMap}, Story/Resources/{Stories,StoryArt}. 가져오기 설정은 Combat/Editor/*Import.cs가 자동으로 맞춘다.
  • .meta를 직접 만들 때는 같은 종류의 기존 그림 .meta를 복사하고 guid만 새 값으로 바꾼다(필터 점, 압축 없음, 밉맵 없음).

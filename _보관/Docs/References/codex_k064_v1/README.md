좌표는 왼쪽 위가 원점. 발선은 발바닥 바로 아래의 경계이며, 마지막 불투명 행은 발선-1이다. 모든 측면은 왼쪽을 본다. 각 파일은 정지 그림 한 장이다.

| 대상 | 앞 / 옆 1배 | 칸 | 중심 / 발선 | 불투명 전체 높이 |
|---|---|---|---|---|
| 곤봉 고블린 | `goblin_front.png`, `goblin_side.png` | 56×112 | x28 / y104 | 96점 |
| 사다리병 빈손 | `ladder_empty_front.png`, `ladder_empty_side.png` | 56×112 | x28 / y104 | 96점 |
| 사다리병 운반 | `ladder_carry_front.png`, `ladder_carry_side.png` | 56×112 | x28 / y104 | 사다리 포함98점, 몸 약95~96점 |
| 오우거 | `ogre_front.png`, `ogre_side.png` | 112×160 | x56 / y152 | 128점 |

위 8개 각각에 `_4x.png`가 붙은 최근접 4배 보기를 제공한다. 오우거는 곤봉·넓은 어깨를 자르거나 가로로 압축하지 않도록 큰 칸을 사용했다. x 중심은 칸의 배치 기준이며, 비대칭 무기/사다리를 포함한 전체 경계 중심이다. 실제 게임 피벗으로 바로 덮어쓰는 계약이 아니다.

## 기준과 팔레트

- 방향: `../codex_hero_octopath_review_v6/APPROVED_DIRECTION.md`, `corrected.png`, `hero_idle_56x112.png`. 실패 원안 generated.png를 스타일 기준으로 삼지 않았다.
- 곤봉 고블린: `Game/Assets/_Project/Art/Characters/Goblin/goblin_walk_attack4.png` 첫 칸. 올리브 피부, 갈흑 모히칸, 작은 황색 눈, 가죽 멜빵/샅가리개, 맨발, 나무 곤봉.
- 사다리병 두 상태: `Game/Assets/_Project/Art/Characters/Static/ladder_goblin_static.png`. 황록 피부, 검은 모히칸, 갈색 스카프/가죽 복장, 손목 붕대, 장화, 나무 사다리. 빈손 모습의 새 무기는 추가하지 않았다.
- 오우거: `Game/Assets/_Project/Art/Characters/Static/ogre_static.png`. 회갈올리브 피부, 대머리, 작은 붉은 눈, 송곳니, 가죽 어깨 장비/끈/허리띠/장화, 뼈빛 돌기가 있는 나무 곤봉.

`palettes.json`은 원본 시트 첫 256×384 칸의 알파128 이상 픽셀에서 실제 RGB를 추출한 결과다. 재질별 명암 목표에 가까운 기존 RGB를 선택한 뒤 최종 PNG의 색을 이 집합으로 제한했다. 최종 불투명 색 수는 고블린16, 사다리병19~20, 오우거18~19다. 외곽선1점·재질3~4단 명암을 목표로 생성/정규화했으나 모든 국소 영역을 손으로 다시 도트 작업하거나 명암 단계 수를 재질별 확정한 것은 아니다. 원본은 미세한 색 차이가 많아 모든 원본 RGB를 그대로 사용하지는 않았다.

생성 원안은 그대로 보존한다. 최종본은 알파128 경계 추출 → 모습 사이 빈 열에서 분리 → 비율을 유지한 최근접 축소 → 기존 팔레트 제한 → 알파0/255 → 칸 배치 순서다. 사다리·곤봉·귀를 자르지 않았다. `manifest.json`의 conversion은 `원본x,y,w,h;축소w,h;배치x,y`이며 SHA256과 칸/발 좌표를 함께 담았다. `build.ps1`은 이 정규화 재현용, `build_review.ps1`은 HTML 재생성용이다.

## 기존 게임의 표시 크기 비율

기본 시트 연결은 `Data/Combat/Enemies/enemy_*.asset`의 GUID를 Characters의 `.meta`와 대조했다. 기본 시트는 고블린 `goblin_walk_attack4`, 사다리병 `ladder_goblin_walk`, 오우거 `ogre_walk`다.

`PerfLabSheetHeights.cs`의 측정 키는 각각240/272/233점, 병사 `archer_static`은300점이다. 오우거 **정적 그림173점을 기본 걷기233점 대신 적용하지 않는다.** `PerfLabArt.cs`의 병사 기준384/측정키 보정, `BattleView.cs`의 적 기본키 보정1, `BattleSim.cs`의 병사1.4×0.25 및 일반적1.2/특수적2.0, `BattleJobs.cs`의 성벽 앞0.33~들판1 배율, `PerfLabSprite.shader`의 칸 높이384 내 실제 인물 비율을 함께 적용했다.

| 대상 | 성벽 앞 보이는 키 계산 | 병사 대비 | 병사96점 비교 |
|---|---|---|---|
| 인간형 병사 | 1.4×0.25×(384/300)×(300/384)=0.350m | 1 | 96점 |
| 곤봉 고블린 | 1.2×0.33×240/384=0.2475m | 0.70714 | 약68점 |
| 사다리병 | 1.2×0.33×272/384=0.2805m | 0.80143 | 약77점 |
| 오우거 | 2×0.33×233/384=0.40047m | 1.14420 | 약110점 |

성벽 앞은 fromWall≤1일 때의 계수다. 30m 바깥부터는 적 계수가1이므로 동일 비율이 아니다. 코드 주석의 '고블린0.4m/오우거0.66m'는 칸의 표시 크기이며 불투명 인물의 실제 키와 구분했다. 실제 카메라 원근/화면 위치/보정에 따른 최종 픽셀 키는 Unity 캡처로 확인해야 한다.

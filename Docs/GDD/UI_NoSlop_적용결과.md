> Claude · 2026-10-16 · 기준 `Docs/GDD/UI_NoSlop.md` · 그림 요청 `Docs/GDD/UI_NoSlop_에셋요청.md`
> **유니티는 열지 않았다.** 유니티 DLL로 모든 어셈블리(Core·UI·Combat·Meta·Frontend·Story·App·PlayProbe·Combat.Tests·SimProbe)를 따로 컴파일해 오류 0을 확인했다. 화면 사진·PlayProbe 실행은 조정 담당이 메인 폴더에서 한다.
> 표의 "판정"은 **코드 기준 자체 검사**다. ◎ = 코드로 지킴, ○ = 지켰지만 사진·영상으로 확인 필요, △ = 일부만 (남은 것 적음).

## 바뀐 구조
- **부품 한 벌** `Game/Assets/_Project/UI/Kit/`: `UiTokens`(색 역할·간격·글자 크기·점 크기·움직임 길이), `UiFonts`(제목 = 명조 계열, 본문 = 맑은 고딕), `UiArt`(그림 이름 한 곳 + 코드 임시 도트 그림), `Ui`(판·글·단추·아이콘·키 표시·어둠막·확인 창·막대), `UiButtonFeel`(단추 손맛), `UiAppear`(펼침·접힘), `UiBar`(지연 막대), `UiPulse`(위급 빛).
- `HLR.Combat`가 `HLR.UI`를 참조한다 (asmdef). 예전 `UiStyle`·`HudStyle` 색·테두리는 지웠다 (`HudStyle`은 그림 불러오기 얇은 길만).
- **단추 이름 = `btn:` + 열쇠.** 보이는 글자를 바꿔도 PlayProbe는 열쇠로 찾는다 (`FindReady`·`ClickPrefix`가 이름도 본다).
- 쓰지 않던 `ResultDetailPopup.cs` 삭제.

## 남은 것·알아 둘 것
1. **사진 확인 필요**: 위 ○ 항목은 조정 담당의 유니티 사진으로 다시 판정해야 한다. 특히 띠 폭(숫자가 길 때), 공방 장부 높이, 말풍선 꼬리 방향.
2. **그림·글꼴 대기**: 코드 도트는 임시 — `UI_NoSlop_에셋요청.md`의 이름으로 Codex 그림이 오면 그대로 바뀐다.
3. **K-049 합칠 때**: `TrapPreparationPanel.Render()`가 통째로 바뀌었다. 지형 탭은 머리 줄 아래 탭 두 개(`Ui.Button(…, UiButtonKind.Tab)`)와 같은 부품(칩·값 줄·황동 [N칸 짓기])으로 옮기면 된다. 설명문(확률 문장)은 F1식 접힌 도움말이나 짧은 꼬리표로.
4. **시험 코드 변경**: PrepFlow는 지점 칸을 바로 누르고(`지점:post_north_squad_1`) 견적 단추 단계가 없어졌다. CannonAim은 `Cannon N State` 낱말(포격·대기)을, Telescope는 "약 …" 무리 표시를 본다.

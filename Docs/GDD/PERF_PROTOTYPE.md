## 1. 목적

"아군 10,000 + 적 50,000이 동시에 움직이고 싸우는 장면을 RTX 2060에서 60 FPS로 돌릴 수 있는 구조인가"를 **게임을 만들기 전에** 확인한다. 결과로 다음을 정한다.

1. 전투 데이터 구조를 이 방식(D-021 G2)으로 확정할지, Entities를 비교할지
2. 시뮬레이션(CPU)과 그리기(GPU) 중 어디가 먼저 한계인지, 품질 옵션을 어떻게 나눌지
3. 투사체·사건 버퍼·풀의 크기 예산

## 4. 구조 (D-021 G2)

```
[생성기] → 적 데이터 배열 ─┐
                          ├→ (Job) 이동: 흐름장 따라 이동, 성벽 도달 시 공격 상태
[배치기] → 아군 데이터 배열 ┤
                          ├→ (Job) 공간 격자 갱신 (칸마다 적 목록)
                          ├→ (Job) 표적 선택: 사거리 안 후보만 격자로 조회
                          ├→ (Job) 발사 → 화살 데이터 풀(슬롯+세대값)
                          ├→ (Job) 화살 이동·명중 (이동 구간 판정, 관통 없음)
                          ├→ 사건 버퍼: 명중 → 피해 일괄 적용 → 사망 확정(1회)
                          └→ 그리기 데이터: 위치·프레임 번호 → GPU 인스턴싱 (종류별 1~수 회 호출)
```

- **데이터:** 적·아군·화살은 `NativeArray` 묶음(위치, 속도, 체력, 상태, 표적 핸들…)으로 관리한다. 개체마다 GameObject를 두지 않는다.
- **병렬 처리:** 이동·격자·표적·화살은 Burst 컴파일 Job으로 처리한다. 사망 제거는 "빈 칸 목록 + 세대값"으로 재사용한다.
- **사건:** 명중·사망은 프레임마다 버퍼에 모아 한 번에 처리한다. 같은 적이 같은 프레임에 여러 번 죽어도 사망 처리는 한 번이다(C-013).
- **그리기:** 사각형 메시 하나 + 스프라이트 아틀라스 머티리얼로 `Graphics.RenderMeshInstanced`(또는 Indirect) 호출. 프레임 번호는 개체별 데이터로 넘기고 셰이더가 아틀라스 칸을 고른다.
  - 도트 그림은 **반투명 대신 알파 잘라내기**(알파 테스트)로 그린다. 깊이 버퍼를 써서 겹침 정렬 비용과 덧그리기를 줄인다.
- **F8 표시:** Boot가 없는 시험 씬이므로 시험 씬 안에 임시로 둔다. 실제 게임의 C-014 연결은 나중에 정한다.

### 5.2 장면 (각 단계마다)

1. **행군:** 적 전원이 성벽으로 이동, 아직 교전 없음
2. **교전 최대:** 아군 전원 사격, 화살 최대, 사망 다수
3. **밀집:** 카메라 화면 안에 적이 최대로 몰림 (그리기 최악)
4. **대량 생성·대량 사망:** 한 프레임에 수천 마리 생성·제거 (순간 지연 확인)

### 5.4 합격 기준 (제안, 사용자 승인 필요)

- 기준 장치(RTX 2060)에서 S3, 1080p 내부 + 2배 확대로 **평균 60 FPS 이상(16.7ms 이하)**, 상위 1% 프레임 **25ms 이하**
- 안정 구간의 프레임당 GC 할당 0
- 사건 정확도: 사망 처리 중복 0, 화살 풀 반환 중복 0
- 네이티브 4K는 합격선이 아니라 **기록값**으로 둔다 (고품질 옵션 판단용)

- **D-023 (2026-10-13) 환산 기준:** 기준 장치를 구할 수 없어 사용자 PC(RTX 3060·i9-13900KF) **성능 시험 빌드**에서 S3 교전 최대 장면 기준 **GPU 11ms·CPU 메인 8.3ms·상위 1% 12.5ms 이하, GC 0**이면 합격(GPU ×1.5, CPU ×2 여유 배수).

### 5.5 측정 환경의 한계

- **에디터 Play 수치는 실제 게임보다 느리다.** 시제품 단계는 에디터 수치로 방향을 판단하고, 합격 판정은 Development Build 측정이 필요하다. 빌드 실행은 첫 마일스톤 범위 밖이었으므로(RULES 12장) **성능 시험용 빌드 예외를 사용자에게 따로 승인받는다.**
- Play와 캡처는 사용자가 한다 (RULES 11.1). AI는 절차와 기록표를 제공하고, 결과를 `[사용자 보고]`로 기록한다.
- 사용자 PC가 기준 장치와 다르면 장치 정보를 함께 기록하고 기준 장치 결과로 보고하지 않는다.

**한계 (판정을 넓게 해석하지 않기 위해):**
1. 화면이 4K가 아니라 3440×1440(점 수 약 60%). 네이티브 4K GPU 시간은 약 1.93 × 1.67 ≈ 3.2ms로 **추정**(측정 아님). 합격선 11ms보다 여전히 낮다.
2. 시험 내용이 단순하다: 적 1종, 화살만(대포·마법 광역·폭발 효과 없음), 직진 이동(흐름장·지형 없음), 함정 없음, 아군은 임시 그림. 실제 전투에는 비용이 더해진다.
3. 측정 표본이 4,096개 상한에 걸렸다(500 FPS 이상이라 10초 중 약 7~8초만 기록). 결과 경향에는 영향이 작지만 실제 전투 코드에서는 상한을 늘린다.
4. RTX 2060 실측이 아니다 (D-023 여유 배수 추정).

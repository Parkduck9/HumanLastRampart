# 스토리 화면 설계 제안 r1

- 상태: **제안 — 구현 승인 아님**
- 작성자: Codex / T-CX-013·CY1-X3·P1-X02 / 2026-10-13
- 데이터 연결은 StoryDataProposal.md의 C-009 승인 후 구현한다.

## 구성

위쪽은 배경과 인물 초상, 아래쪽은 이름·대사 패널·다음 버튼이다. 인물 없는 줄에는 초상을 숨긴다. 처음에는 대사 전체를 바로 보여 주며 타이핑 연출·자동 넘김·전체 건너뛰기는 뒤로 미룬다. 마우스 클릭과 UI Submit은 같은 다음 동작으로 연결한다.

한 줄을 누르면 다음 줄을 표시하고 마지막 줄에서는 입력 차단 후 Done을 한 번 보낸다. 스토리는 다음 씬을 직접 열지 않는다. 첫 스토리와 패배 엔딩 모두 같은 화면을 사용하되 Kind와 데이터가 맞아야 한다. 패배 엔딩은 보상/정비를 열지 않고 App이 메인으로 복귀한다.

## 예보·오류

날씨 힌트는 C-009 ForecastHint 줄에만 표시한다. 일반 대사마다 예보를 추첨하지 않고 Core BattleForecast를 사용한다. 초기 날씨/밤낮 전달만 추천하며 예보 변화 시각은 노출하지 않는다.

StoryId 없음, 잘못된 Kind, 정의·줄 누락은 다음을 막고 ReportDataError로 Boot 안내에 전달한다. 스토리를 종료했다고 보상이나 전투 번호를 직접 변경하지 않는다. OnExit에 UI 구독·인물·배경·읽기 상태를 정리한다.

검증: 1줄/여러줄/패배 엔딩, 연타·Submit으로 마지막 완료 중복 없음, 빈/잘못된 데이터의 E2 안내, 같은 입력의 같은 날씨 힌트, 배경/초상 없는 줄, 긴 한글 대사가 패널 밖으로 나가지 않음. 시각 배치는 승인 시안을 따로 확인한다.

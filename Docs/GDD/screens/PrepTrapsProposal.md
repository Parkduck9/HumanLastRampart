# 바퀴 4 정비 함정 설계안 r2

- 작성자 Codex / T-CX-032
- 상태: 사용자 화면 흐름 승인. 환불 불가능 확정. D-050 격자 배치·점화식 반영. 회수 보완·새 데이터 인터페이스는 검토 대기이며 구현 완료가 아니다.
- 담당 제안: Codex 정비 구매·재설치·회수 선택/결과 반영, Claude Core 판정·전투 발동/피해/소비·전투 결과/App 연결·CYCLES 관리.
- 근거: FirstRead, 기존 Prep 설계, 승인 D-022·C-008/P1-C14·C-015·C-016. 새 인터페이스는 제안 상태로 남긴다.

## 1. 화면 구성

현재 정비의 수리·병력 옆에 ‘함정’ 진입 버튼을 추가한다. 함정 화면은 구매/재설치와 회수 두 탭으로 나누고, 상단에 보유 골드·다음 전투 지형·선택 지형의 보관/설치 수를 보여 준다. D-050에 따라 중앙 성의 성벽 밖 넓은 격자 구역을 사용한다. 칸 5m, 성벽에서 10~80m, 성벽 폭 전체이며 언덕 등 설치 불가 칸을 표시한다. 한 칸에 하나만 설치한다.

구매/재설치 탭은 다음 전투 지형의 설치 지점을 고른다. 오른쪽에는 함정 이름·정의 가격·발동/피해 범위·지도 표시 여부·재고 사용 또는 골드 구매를 표시한다. 한 종류(기존 일회용 폭발 함정)부터 시작한다. D-050 승인값은 가격 25골드, 상점 초기 재고 6개·정비마다 +3·최대 12개다. 회수품 보관함과 상점 판매 재고는 별도로 표시한다. 점화는 지도 표시 클릭 후 0.5초, 피해 300·반경 6m이며 기타 확률·구덩이 효과는 D-050을 따른다.

회수 탭에서는 설치물이 남은 지형을 선택하고 지도에 표시된 함정만 목표로 고른다. 투입 분대 하나와 경로(출발점→표시된 목표→출발점)를 확인한다. ‘회수하지 않음’을 제공한다. 첫 범위는 결과 목록만 표시하고, 파견 병사 실시간 이동 연출은 만들지 않는다.

## 2. 구매·재설치 흐름

지점 선택 → 종류/재고 선택 → 지도 표시 체크 → 가격/격자 칸/효과 견적 → 확정한다. 일반 구매는 성공 때만 골드 차감과 NewInstanceId("trap")를 실행한다. 보관함 재설치는 골드 대신 TrapStock을 1개 사용하고 새 설치물 ID를 발급한다. 재설치 실패 때 재고·ID는 그대로다. 회수 전 설치물의 동일 TrapId 유지와, 보관함에서 새 설치물로 꺼내는 것은 구분한다.

빈 설치 가능 칸·현재 지형·정의·가격·골드/재고·중복 ID·유한 좌표를 검사한다. SlotId는 설치 출처, ActualX/Z는 설치 칸 가운데 좌표, Marked가 true일 때만 MarkX/Z에 해당 위치를 저장한다. 지도 표시하지 않은 실제 위치를 회수 UI로 노출하지 않는다.

정비 중 무료 이동 정책은 과거 SlotId 단독 규칙과 실제 좌표/낡은 지도 규칙을 혼동하지 않도록 새 판에서 확정한다. 사용자가 구매·재설치·회수 흐름에 동의했다. 환불은 불가능하며 후속 기능으로도 예약하지 않는다. 회수는 골드 반환 없이 보관함에 함정을 돌려놓는 기능이다. 판매·자유 위치 이동은 이번 범위에 넣지 않는다. 마지막 전투 뒤 다음 전투가 없다면 구매/재설치를 막고 회차 종료로 안내하는 안을 제안한다.

## 3. 회수 흐름과 중복 방지

선택 지형·살아 있는 분대·지도 표시 목표·파견 경로와 위험 안내를 확인 → 한 번 실행 → 성공/폭발/새로 발견/손실 목록을 표시한다. 정확한 미발견 함정 위치와 확정 손실을 실행 전에 보여 주지 않는다.

동일 RecoveryId와 시드는 결과를 재추첨하지 않는다. 결과를 보면서 취소해 다른 ID로 반복 추첨하는 방식도 만들지 않는다. 주문 확정 후 그 결과를 검사해 한 번에 반영하고 LastAppliedRecoveryId를 기록한다. 잘못된 결과는 보관함·설치물·병력·기록 모두 보존하고 E2로 안내한다.

성공 회수는 해당 TrapId를 제거하고 종류별 보관 수를 증가시킨다. 경로에서 폭발한 함정은 제거만 한다. 새로 확인한 함정은 지도 기록을 실제 위치로 갱신한다. 선택 분대의 손실만 반영하며 0명 분대는 제거한다. 다른 지형 함정과 LastBattle/보상 반영 ID는 유지한다.

## 4. 구현 전에 풀어야 할 연결 문제

1. R1: 현재 RecoveryOrder에 투입 인원이 없고 ResolveRecovery가 분대 전멸 후에도 진행할 수 있다. Claude가 인원/전멸 중단을 포함한 C-015 변경안을 정리하고 사용자 승인 뒤 Core를 먼저 보완해야 한다. Meta에서 손실을 자르는 것만으로 회수 성공을 허용하지 않는다.
2. R2: 기존 코드는 지도 위치와 실제 위치 차이가 DetectRadius 이하면 처음부터 아는 함정으로 친다. 지도 일치 허용 오차와 탐지 반경을 분리할지 사용자 결정이 필요하다. 임의 거리 값을 넣지 않는다.
3. R3: D-050과 새 C-005 제안은 지도 표시를 BattleSetup에 전달하도록 변경한다. 이전 r1의 지도 필드 제거 제안은 대체한다. 지도 클릭은 Mark 좌표, 실제 폭발·피해는 Actual 좌표를 사용하도록 경계를 검토한다.
4. 현재 BattleResultApplier는 소비/이동 결과가 있으면 미지원으로 거부한다. Claude가 실제 함정 결과를 내보내기 전에 Codex가 C-007 v1.1 소비·이동 검증/원자적 반영을 확장하고 함께 QA해야 한다.

이 문제들을 해결하지 않고 화면만 연결해 ‘함정 완료’로 처리하지 않는다. 구매/재설치와 회수는 서로 의존 조건을 구분해 순차 구현할 수 있다.

## 5. 검증 기준

빈/점유/설치 불가 칸, 골드·재고 부족, 다른 지형, 잘못된 정의/좌표, 중복 TrapId 실패 무변경. 같은 구매·재설치·회수 명령 중복 무변경. 실제 위치와 지도 기록 분리. 다른 지형 함정 보존. 분대 전멸 뒤 경로 중단. 소비/이동 중복 결과 거부. 전투→결과→정비→회수→보관→다음 재설치 흐름. 화면/게임 QA는 Claude가 맡고 Codex는 자기 거래·반영 소스를 검증한다.

## 6. 사용자 승인과 남은 검토

- 사용자 “아니 딱맞아 환불은 불가능”에 따라 구매·설치·보관 재설치·회수 화면 흐름에 동의한 것으로 기록한다. 환불은 금지한다.
- D-050의 격자·가격·재고·점화식 등 기존 승인 사항은 다시 묻지 않는다.
- 회수 R1·R2와 새 C-008 r6/C-004 v1.3 등 데이터 형태는 Claude와 검토 후 연결한다. 화면 흐름 승인만으로 미확정 API를 구현하지 않는다.
- HTML은 `_HTML/codex_함정설계_v1.html`에 계속 갱신한다. 지도는 구성 예시이며 실제 지형·전투 실행 결과가 아니다.

## 7. 중앙 성과 우회 적 경고 요구 (전투 담당 전달)

사용자 요구: 지도 가운데 성이 있고 적은 대체로 정면에서 접근한다. 전략적인 적은 돌아서 늦게 등장할 수 있다. 병사가 늦게라도 발견하면 자동으로 두 명이 양쪽으로 퍼져 지휘관(플레이어)을 찾아가고, 찾으면 적이 온다고 알려준다.

Claude의 전투·Core 담당 설계로 전달한다. 탐지 거리·우회 비율·경고 빈도·파견 중 전투 참여·보고 후 복귀 정책은 아직 정하지 않았다. 기존 명령 전달 전령과 이번 발견 보고 전령의 관계도 검토해야 한다. 다음 두 사항은 사용자에게 채팅에서 질문한다.

1. 경고는 우회 적 발견에만 보낼지, 정면 적도 새 무리 발견마다 보낼지.
2. 기존 방어 병사 두 명을 잠시 파견하고 보고 후 복귀시킬지, 별도 전령 두 명으로 둘지.

## 변경 기록

- r1: 최초 화면 구성 제안.
- r2: 사용자 흐름 승인·환불 금지 반영, 최신 D-050 격자/점화식/재고 및 지도 필드 경계 반영. 중앙 성·우회 적·자동 두 전령 요구 전달. 전투 구현 및 Unity QA는 수행하지 않음.

## 전투 경고 요구 사용자 후속 답변

- 우회 적 발견 시에만 전령을 보낸다. 실제 방어 병사 두 명은 공격에서 잠시 빠진다.
- 양쪽으로 출발하여 지휘관을 찾으면 보고 후 복귀한다. 다른 한 명은 이미 보고가 되었어도 한 바퀴를 마치고 복귀한다. 못 찾은 쪽도 한 바퀴 후 복귀한다.
- 지휘관이 발견 병사와 같은 성벽에 있으면 두 명 모두 출발하지 않는다. 같은 성벽에 있다는 사실을 곧바로 적을 인지했다고 해석하지 않는다.
- 지휘관이 못 알아채고 다른 성벽으로 이동했을 때 경고할 조건은 사용자 고민 중이며 미정이다. 이 조건은 구현하지 않는다.
- 위 7장의 두 질문은 답변되었으며 이 후속 답변이 최신 기준이다. Claude 전투 담당에게 M-CX-054로 전달 기록.

## Codex 데이터 약속 검토 (T-CX-034)

검토 대상: C-008 r6·C-004 v1.3·C-005 지도 필드 추가·C-010 v1.5, 실제 작업 중 Core/TrapGrid·TerrainDef·TrapDef·CampaignFactory·BattleResultApplier. 읽기 검토이며 Unity/게임 실행 시험은 하지 않았다.

### 동의

- 공용 순수 TrapGrid로 정비와 전투 좌표를 일치시키는 방식, 원래 설치 칸을 SlotId로 보관하는 방식에 동의한다. 이동한 함정도 회수 전에는 원래 칸을 점유한다는 현재 제안도 따른다.
- 상점 TrapShop과 회수품 TrapStock을 분리하고, 구매는 골드/상점 재고, 재설치는 보관 재고만 사용하는 방식에 동의한다. 환불은 불가능하다.
- 최초 정비가 전투2 앞이므로 보충 기록 초기값2를 사용하는 의도는 CampaignFactory 주석과 일치한다. 최초6개→다음 정비9개→다음12개, 같은 정비 재진입은 증가 없음으로 확인한다.
- 지도 Mark 좌표로 클릭하고 Actual 좌표로 폭발시키는 경계에 동의한다. 소비 목록은 터진 함정만 포함하며 불발은 남긴다.

### 보완 요청

1. V1 칸 ID: TryParse는 `cell_0_01_0`과 `cell_0_1_0`을 같은 칸으로 해석한다. 문자열 ID만 비교하면 동일 칸 중복 설치가 가능하다. 생성한 정규 ID와 동일한 문자열만 허용하거나 파싱 좌표로 점유를 비교하는 계약이 필요하다. Center/CellId 자체에는 범위 검사가 없으므로 호출 전 검증 경계도 명시한다.
2. V2 정의 검사: TrapCellSize 유한/양수, CastleHalfSize 유한/양수, Near>=0, Far>Near, 격자 범위가 들판 안에 있는지, 언덕 목록 null/좌표 유한/반경 양수 여부를 검사한다. 함정 확률은0~1, 가격/재고 비음수·초기<=최대, fuse/radius 유한/양수, 구덩이 속도배율 범위 등은 App 시작 검사의 담당·조건을 명시한다. 이번에 읽은 DefinitionLookup에는 새 필드 관련 검사를 찾지 못했다. 작업 중 파일이므로 최종 구현의 결함으로 확정하지 않는다.
3. V3 재고 보충: 정의별 재고 ID 유일성·미등록 정의·음수 수·상한을 검사하고 모든 종류의 다음 재고를 준비한 뒤 목록과 보충 전투 번호를 함께 반영한다. 뒤에 잘못된 항목을 만나 앞 종류만 증가하는 부분 반영을 금지한다. 정의 오류 시 초기 재고로 조용히 재생성하지 않는다.
4. V4 결과 반영: 결과 TrapId는 이번 setup의 해당 지형 설치물이어야 한다. 소비/이동 각각 중복·서로 교집합·알 수 없는 ID·다른 지형·NaN/무한대 이동 좌표를 거부한다. 시작과 현재 해당 함정 상태 일치를 검증하고, 전부 검사한 후 복사 목록에 소비 제거/Actual만 이동을 적용한다. Mark·SlotId·다른 지형·상점/보관 재고는 보존한다. 골드/영웅/병사/성벽과 함께 한 번에 반영하고 LastAppliedBattleRunId는 마지막에 기록한다. 이동 좌표 허용 범위는 Claude 전투의 이동 제약과 맞춘 뒤 명시한다.
5. V5 문서 버전: C-005는 기존 v1.3(무배치 주인공/마법사 참가) 이후 새 지도 변경을 v1.2로 적었다. 덮어쓴 버전으로 오해하지 않게 기존 참가 규칙을 유지한 새 버전으로 정리한다. CampaignState.SlotId의 TrapSlotDef 주석도 새 칸 의미로 정리한다.

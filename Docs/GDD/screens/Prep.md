# 정비 화면 설계 제안 r1

## 구성과 순서

상단에 다음 전투 번호·보유 골드·현재 지형을 고정하고, 수리/병력/함정 패널을 탭으로 전환한다. 오른쪽은 선택한 항목의 비용·효과·확인 버튼, 아래는 전투 준비 완료 버튼이다. 성벽 북/동/남/서를 선택하고 해당 성벽의 체력·지점·병력을 보여 준다. 큰 병력 인원을 얼굴 수만큼 UI 오브젝트로 만들지 않고 분대·지점 요약으로 나타낸다.

수리: 4개 성벽의 현재/최대 체력과 비용 확인 → 구매 전 골드/범위 검증 → 성공 후 갱신. 병력: 병종별 모집·가용/배치 인원 → 성벽 지점 배정. 대포 지점에는 대포 운용병만, 일반 분대 지점은 허용 병종 규칙을 따른다. 죽은 영웅의 회복/퇴장은 별도 정책 확정 전 조작하지 않는다. 가격·모집 수·수리 비율은 데이터 약속 추가 승인 후 구현한다.

함정: 현재 지형 설치 지점 선택 → 보관함 재설치 또는 골드 구매 → 지도 표시 여부 선택 → 고유 TrapId 발급. 첫 지점·실제 위치·지도 기록을 분리한다. 함정은 해당 지형에 남으며 다른 지형 전투에서 임의로 소비하지 않는다. 다음 전투 지형은 기존 CampaignStartDef 순서로 계산한다.

## 1회차 회수와 확장

첫 범위는 지형·분대 하나·지도에 표시된 회수 목표를 고르고 예상 선택을 확인한다. 회수하지 않음도 제공한다. Core TrapRules의 결과를 목록으로 보여 주고 검증→일괄 적용→RecoveryId 마지막 기록 순으로 처리한다. 새 계산을 하려고 화면을 다시 여는 방식으로 결과를 재추첨하지 않는다.

지도 위 동시 파견·얼굴 원형 아이콘 이동·폭발 연출·오른쪽 접이식 실시간 보고서·귀환 보너스·제한 지형 편집은 다음 마일스톤의 사용자 요구로 보관한다. 현재 순수 계산 방식으로 이미 구현된 것처럼 표시하지 않는다. 소규모 경로 위험·전멸 뒤 회수 중단 정책은 C14 검토 사항을 확정한 뒤 연결한다.

## 완료·검증

전투 준비 완료는 Done만 전달한다. App이 새 BattleSetup을 생성하며 정비가 이전 전투 번호나 결과를 직접 교체하지 않는다. 현재 판 난이도를 이 화면에서 바꾸지 않는다. 마지막 정비 이후 메인 복귀는 App 담당이다.

검증: 골드 부족·잘못된 지점·0명 분대·중복 배치·재설치 재고 부족 시 무변경, 다른 지형 함정 보존, 표시/실제 위치 분리, 같은 회수 결과 중복 무변경, 회수 포기, 마지막 전투 이후 정상 종료. 함정 소비/회수 API 추가는 Phase3에서 별도 검증한다.

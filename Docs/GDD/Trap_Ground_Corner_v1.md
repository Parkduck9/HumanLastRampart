> **정정 (2026-10-20 사용자):** 자유 배치·우클릭 돌리기는 **함정이 아니라 지형 손질의 토벽과 언덕** 이야기였다. 아래 1장의 규칙(칸 없이 놓기, 오른쪽 누르기 45도 돌리기, 놓을 수 없는 곳 붉게)은 **토벽·언덕**에 적용한다. 토벽은 긴 판이라 방향이 실제로 길을 막는 모양을 바꾸고(돌리면 비스듬한 벽), 언덕은 둥근 덩어리에 긴 방향을 준다. 지형 칸(5m 격자)으로 길 찾기를 하므로, 놓은 토벽·언덕이 덮는 칸을 계산해 막힘으로 바꾼다. 함정은 지금 그대로 둔다
> 모서리 오류: 2026-10-20 고침 — 발판 윗면 통로 돌, 사진기 옆 탑 숨김. 연속 14장 기록에서 사진기 높이 6.25·숙임 25도·발 높이 4.0이 끝까지 그대로임을 확인

## 1. 함정 자유 배치 + 우클릭 돌리기 (→ 토벽·언덕에 적용, 위 정정 참고)

### 지금
- 정비 함정 지도에서 성벽 앞 5m 네모 칸(성벽에서 10~80m)에만 놓는다(D-050). 칸 선이 보여서 "앞쪽에 네모칸만" 있는 모양

### 바꿀 모습
- **칸 없이 들판 아무 곳**에 놓는다. 함정 지도 위에서 마우스를 따라 반투명 '놓을 모습'이 움직이고, 왼쪽 누르기 = 놓기
- **오른쪽 누르기 = 45도씩 돌리기** (놓기 전 미리보기에서. 놓은 뒤에는 그 함정을 다시 집으면 돌릴 수 있음)
- 놓을 수 없는 곳은 놓을 모습이 붉게: 성벽에서 10m 안·80m 밖, 언덕·토벽·바위·나무 덩이 위, 다른 함정과 3m 안, 성 안
- 지금 함정은 둥근 폭발이라 돌려도 효과는 같다. 방향은 **앞으로 생길 모양 있는 함정**(가시 줄·통나무 굴리기 등)을 위해 미리 넣는다 — 지금은 그림 방향만 바뀐다 (질문 1)

### 데이터 (CONTRACTS C-008 새 판 필요)
- 설치 기록에 `Rotation`(도) 추가. 위치는 이미 실제 좌표(X·Z)로 저장하므로 칸 번호만 쓰지 않게 바꾼다
- 예전 저장 파일: 칸 번호 → 칸 가운데 좌표로 옮겨 읽는다(돌림 0)
- 전투: 함정 그림을 방향대로 눕혀 그린다. 터지는 범위·점화는 그대로

### 순서
1. Core 데이터·규칙(놓을 수 있는가 검사 함수) + 시험 → 2. 정비 함정 지도 놓기·돌리기 화면 → 3. 전투 그림 방향 → 4. 저장 호환 시험

## 2. 자연스러운 땅 (옥토패스 방향)

### 왜 "붕 뜬" 느낌인가 (오늘 사진에서)
1. **바탕이 한 장의 고른 초록**: 아래 깔린 땅에 변화가 없어서, 그 위 무늬가 스티커처럼 떠 보인다
2. **무늬 가장자리가 딱 끊김**: 그림 바깥이 투명하게 잘려 있어 바닥과 섞이지 않는다
3. **세운 소품(덤불·무기)에 그림자가 없음**: 땅에 붙은 느낌이 없다
4. **적이 다니는 길이 땅에 드러나지 않음**: 실제 전장이라면 수천 마리가 지나간 길은 흙이 드러나고 짓밟혀 있어야 한다

### 잘 만든 HD-2D 땅의 공통점 (옥토패스 계열)
- 바닥은 **반복 질감 여러 장을 부드럽게 섞은 것**(풀·짓밟힌 풀·흙·진흙), 경계가 번져 있음
- 소품 아래 **작고 부드러운 그림자**, 바닥과 같은 색 계열
- 큰 무늬보다 **작은 변화가 넓게** — 멀리서 보면 결이 있고, 가까이 보면 도트

### 설계
1. **바닥 섞기 셰이더 (Claude)**: 반복 질감 4장(풀 · 짓밟힌 풀 · 흙 · 진흙)을 낮은 해상도 '섞기 지도' 한 장으로 섞는다
   - 섞기 지도는 게임이 만든다: 적이 오는 깔때기 = 흙길(가운데 진하게, 가장자리 번짐), 성벽 앞 15m = 진흙·짓밟힘, 언덕 = 풀, 그 밖 = 풀과 짓밟힌 풀이 잡음으로 섞임
   - 무작위 지형(언덕·나무·바위) 둘레는 풀이 진하게
2. **무늬(데칼)는 바닥 질감과 같은 색**에서 만들고 가장자리를 번지게(알파를 몇 점에 걸쳐 줄임), 바닥 위에 '덮기'보다 '어둡게·밝게 섞기'로 깐다 — 스티커처럼 뜨지 않게
3. **세운 소품 아래 작은 그림자 판**(둥근 흐린 얼룩)
4. 전투 중 생기는 자국: 불바다 자리는 그을음, 폭발 자리는 구덩이로 **그 자리에 남는다**(지금은 처음부터 흩뿌려 둠 → 사건이 생긴 곳에만)

### 코덱스 그림 (카드 지시문은 크레딧이 채워진 뒤)
- 반복 질감 4장(풀·짓밟힌 풀·흙·진흙): 이어 붙여도 이음새 없음, 지금 캐릭터와 같은 점 크기, 노멀맵 짝
- 경계 번짐용 잡음 무늬 1장
- 데칼 다시: 바닥 질감 색에서 뽑고 가장자리 번짐, 그림자 판 2종
- 검토 페이지: 실제 전투 사진 구도에 깐 전후 비교, 고블린이 잘 보이는지 확인

## 3. 모서리 돌 때 땅이 위아래로 움직이는 오류

### 지금 확인한 것 (자동 시험 사진: 모서리 돌기 전·중·후)
- **모서리 발판 윗면에 질감이 없다**: 모서리 발판은 '탑 벽' 질감을 상자째 바른 것이라 윗면이 늘어나 거의 민무늬 밝은 판으로 보인다. 통로(돌 바닥)와 색·결이 확 달라서, 지나갈 때 바닥이 바뀌며 튀어 보인다
- **탑이 화면을 가린다**: 도는 동안 사진기가 모서리 탑 바로 옆을 지나가며 탑 벽이 화면 절반을 덮는다
- 사진기 높이·숙임 각도는 도는 동안 바뀌지 않는다(코드 확인) — 사진기 자체가 오르내리는 것은 아니다

### 원인 후보 (확인 순서)
1. 모서리 발판 윗면 높이·질감이 통로와 달라서 바닥이 '올라왔다 내려가는' 것처럼 보임 — 가장 유력
2. 도는 동안 사진기가 대각선으로 미끄러지며(발 위치를 부드럽게 따라감) 먼 들판 끝·먼 산 띠의 보이는 높이가 각도에 따라 바뀜
3. 미니어처 흐림(초점 띠)이 각도에 따라 위아래로 움직여 바닥이 출렁여 보임

### 고칠 방법
1. 모서리 발판 윗면에 **통로 돌 질감**을 통로와 **같은 높이**로 덮는다(통로 덮개 판과 같은 방식) → 통로가 끊김 없이 이어짐
2. 사진기가 탑에서 일정 거리 안이면 **탑을 반투명으로** 하거나, 도는 동안 사진기를 성 안쪽으로 조금 당겨 탑을 피한다
3. 확인용 자동 시험: 모서리를 도는 동안 매 장면의 사진기 높이·초점 띠 위치·화면 속 지평선 높이를 기록하고, 사진 열 장을 이어 붙여 출렁임이 없어졌는지 본다
- 회원님이 보신 '위아래로 움직임'이 위 셋 중 어느 것인지 확실하지 않다. 고친 뒤 이어 붙인 사진으로 함께 확인하자 (질문 2)

## 질문
1. 함정 돌리기: 지금 함정(둥근 폭발)은 돌려도 효과가 같다. 그림 방향만 바뀌어도 괜찮은지, 아니면 이번에 방향이 의미 있는 함정(예: 가시 줄)을 하나 같이 만들지
2. 모서리 오류: 위 고칠 방법 1·2를 먼저 하고 사진으로 확인해도 될지
3. 땅: 위 설계(바닥 섞기 + 데칼 다시 + 그림자)로 진행해도 될지 — 코덱스 그림은 크레딧이 채워진 뒤

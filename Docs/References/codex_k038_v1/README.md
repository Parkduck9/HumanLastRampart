## 제작과 참조
내장 imagegen으로 대포병·화상 원안을 생성했다. 정확한 최종 프롬프트는 `prompts.json`, 원안은 `cannon_pull_source.png`(3열×2행), `burn_source.png`(가로6칸)에 보관한다. 첫 대포병 생성은 칸 간 여백이 부족하여 미채택했고, 3열×2행으로 다시 생성한 원안을 채택했다.

참조는 Game의 `Art/Characters/Run/cannon_crew_run.png`, `Art/Characters/Goblin/goblin_walk_attack4.png`, `Art/Characters/Static/ogre_static.png`, `Art/Battle/Resources/BattleArt/Effects/torch_flame.png`, K-016의 `Docs/References/codex_weapons_fire_v1/cannon_recoil_sheet.png`다. K-016 대포는 기존 재질과 형태를 참조해 옆모습으로 재생성했으며 기존 정면 PNG 자체를 축소한 것은 아니다. 참조 파일은 읽기만 했다. 적·대포병 비교용 사본 3개는 이 폴더의 `reference_*.png`다.

`build.ps1`은 원안을 칸별 분리하고 공통 배율·최근접 축소·하단 정렬로 시트를 만든다. 알파128 초과 영역을 기준으로 경계를 계산하므로 원안의 아주 옅은 외곽 잔여물이 잘릴 수 있다. 내용 덧칠·프레임 복제·관절 보간은 하지 않았다. 원래 알파는 보존한다. 지도 원은 정밀한 원과 룬 선을 System.Drawing으로 제작했다. `manifest.json`에 원안 분할 좌표·배율·최종 칸·기준점을 기록했다. `build_html.ps1`로 내장 HTML을 갱신한다. Game 폴더에 넣지 않은 시안이므로 Unity `.meta`를 생성하지 않았다.

## 직접 확인
최종 대포 6칸, 작은 화상 시트, 불바다 범위 원을 이미지로 열어 방향·내용·여백을 확인했다. PNG 7종의 규격·모서리 알파0·SHA256은 `qa_assets.json`에 있다. HTML JavaScript 구문과 DOM·캔버스 모형 실행 11항목(준비 완료, 그리기, 정지/재생, 6칸 수동 넘김, 외부 이미지·스크립트 경로 없음)을 확인했다(`qa_html.json`). 합성 모아보기는 `contact_review.png`다.

실제 브라우저를 열려고 했으나 in-app browser를 사용할 수 없다는 도구 응답으로 화면 검증을 수행하지 못했다. 모형 검증은 실제 브라우저 렌더링·사용자 조작 검증이 아니다. Unity 실행·Play·게임 캡처는 수행하지 않았다. Git 쓰기 및 협업 live 기록 수정은 하지 않았다.

## 미확정·남은 질문
1. 대포와 병사를 같은 칸에 넣으면 병사 실체가 약156px로 줄어 기존 달리기 약210px와 차이가 난다. 이 조합 크기를 채택할지, 병사 크기를 유지하도록 인물·대포를 별도 레이어로 제작할지 사용자 확정이 필요하다.
2. 양손이 포가를 붙드는 파지와 짧은 보폭, 6→1 연결, 바퀴살 회전은 외형 검토 대상이다. 두 손이 겹쳐 보이며 독립된 손 두 개가 명확히 드러나지는 않는다. 제복의 팔레트·요소는 유지했으나 세부 도트가 원본과 완전히 같지는 않다.
3. 작은·큰 화상은 같은 불꽃 묶음을 다르게 축소한 것이다. 실제 고블린·오우거 크기, 방향에 따른 겉칠 위치, 불꽃 점멸 및 잔여 알파 가장자리는 게임 연결 후 확인해야 한다.
4. 범위 원 색·룬·불투명도와 실제 마법 반지름, 사거리 밖일 때 클릭 가능 여부는 이 그림으로 확정하지 않는다.
5. 검토 HTML 실제 브라우저 화면, 작은 화면 배치·클리핑·재생 자연스러움, 실제 게임 속도·판정·가림은 미검증이다. 사용자 확정 후 Claude가 연결하고 실제 게임 캡처와 비교한다.

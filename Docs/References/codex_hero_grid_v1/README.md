# 플레이어 고정격자 걷기 시트 v1

- 작성자: Codex / T-CX-027
- 사용자 요청: 기존 그림을 유지한 시트 재배치 해결안 실행.
- 원본: 승인 v8 JSON과 front_back v6·side v4 PNG. 외형·눈 수정·4프레임 선택 유지.
- 결과: `hero_walk_grid.png` 투명 RGBA 1024×1152, 4열×3행. 칸256×384, 모든 칸 발 위치(128,352), 왼쪽 아래 정규화 피벗(0.5, 0.0833333), 칸 비율2/3.
- 행(위→아래): 0 후면 걷기, 1 왼쪽 걷기, 2 정면 걷기. 열은 기존 선택 순서0~3. 정지에는 각 행의 프레임1 또는3을 사용할 수 있지만 별도 정지 모션을 만든 것은 아니다.
- 오른쪽: 왼쪽 행 좌우 반전. 기존 오른쪽 순서까지 유지하려면 열 순서2·3·0·1로 읽는다. 좌우 반전된 행을 따로 추가하지 않았다.
- **방향당4프레임이며, 총12칸이다. 12프레임 보간 애니메이션이 아니다.**
- 달리기는 아직 제작하지 않았으며 달리기 행·공격 행은 없다. 걷기3행을 먼저 연결할 수 있다는 M-CL-044에 맞췄다.

## 재배치 방법

`build_sheet.py`는 기존 JSON crop·pivot·unitScale를 읽고 최근접 방식으로 축척을 통일한 뒤 발 기준점에 정렬한다. 개별 프레임 높이에 맞춰 매번 다시 확대하지 않는다. 머리 고정·팔다리 분리·눈 수정·색상 추가·그림 생성은 하지 않는다. 기존 미리보기의 unitScale를 그대로 사용해 기존 방향별 크기 정규화를 유지한다. 원본 PNG와 JSON 해시를 생성 전후 비교한다.

RGBA를 그대로 붙이고 알파를 두 번 곱하지 않는다. PNG 픽셀 자료는 재배치/최근접 크기 변환 결과로서 원본 파일 바이트와 같지는 않지만 원본 파일은 수정하지 않는다. 결과는 새 sibling 경로에 보관한다.

## 확인 결과와 한계

12칸 모두 내용 존재·칸 내부 여백·잘림 없음·동일 발 기준점, 내보낸 PNG와 생성 데이터 정확 일치, 원본3파일 해시 유지 확인. 소형/방향/재생·프레임 버튼은 preview.html에서 검토한다. 외형과 포즈는 원본에 있던 차이를 유지한다.

현재 Game 폴더에는 복사하지 않았다. 실제 GPU UV 행 순서·좌우 반전·Point 필터/압축 설정·캐릭터 표시/이동·Unity Play는 Claude 담당이며 미검증이다. 게임 연결 시 임포트 피벗만 바꾸는 것이 아니라 SheetLayout의 공통 피벗도 이 값으로 전달해야 한다.

## 브라우저 확인
자동 재생 렌더 수 2→63 증가, 일시정지·다음프레임·오른쪽반전(행1/칸2)·후면 복귀·재생 재개 확인. 내장 PNG1024×1152 로드, 좁은304px 화면 가로 넘침 없음. HTML은 PNG를 내장해 서버 없이도 재생할 수 있다. 실제 Unity 연동은 아직 확인하지 않았다.

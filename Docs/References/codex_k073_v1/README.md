# K-073 궁수 동작 1판

검토 페이지: [`codex_K-073_궁수동작_v1.html`](../../../_HTML/4_그림_캐릭터/codex_K-073_궁수동작_v1.html). 그림·스타일·스크립트를 내장해 서버 없이 직접 열 수 있다. 새 궁수와 현재 게임 시트를 나란히 재생하며 일시 정지, 한 칸 이동, 좌우 뒤집기, 속도 변경을 제공한다.

## 제작 기준

- D-080 정정의 처음 생성한 주인공 6판 방향과 D-081의 인물 약 73픽셀을 적용했다. 카드 제목의 크기 미정 표시는 D-081로 해소됐다.
- 기준 인물은 `codex_k070_v1/archer_back_96x128.png`, 생성 참고는 같은 폴더의 궁수 앞·뒤 4배 그림이다. 갈색 머리, 남색·크림색 군복, 가죽 화살통과 큰 장화를 유지했다.
- 후면 대기는 K-070 원본을 그대로 사용했다. 나머지는 기본 이미지 생성 도구로 동작 원안을 생성한 뒤, 연결 영역 추출·최근접 축소·32색 양자화·이진 알파·칸 배치로 규격을 맞췄다. 인물 외곽의 1~2픽셀 고립점은 제외했다. 생성 원안은 `*_generated.png`, 생성 프롬프트는 `prompts.json`에 보관했다.

## 전달 시트

| 동작 | 게임용 파일명 | 칸 수 | 왼쪽부터 순서 |
|---|---|---:|---|
| 후면 대기 | `archer_static.png` | 1 | 대기 |
| 측면 달리기 | `archer_run.png` | 4 | 오른발 전진 → 교차 → 왼발 전진 → 교차 |
| 후면 사격 | `archer_fire.png` | 6 | 준비 → 당기기 → 조준 → 발사 → 회복 → 다음 화살 준비 |
| 쓰러지기 | `archer_fall.png` | 4 | 피격 → 무릎 꺾임 → 옆으로 넘어짐 → 쓰러짐 |

각 동작은 원본 `*_native.png`, 게임용 파일, 원본 정수 4배 `*_4x.png`를 제공한다. 전체 15칸 확인용은 `contact_sheet_4x.png`다.

- 원본 칸 96×128, 발 기준 (48,120), 인물이 차지하는 마지막 행 y=119.
- 게임용 칸 288×384, 발 기준 (144,360). 원본을 정확히 3배 최근접 확대했다.
- Unity 왼쪽 아래 기준 정규화 피벗은 **(0.5, 0.0625)**. 게임용 아래 여백은 24픽셀이다. `manifest.json`의 발 좌표는 왼쪽 위 기준이다.
- 달리기는 오른쪽을 보는 측면이다. 반대 방향은 게임에서 좌우 반전한다. 사격은 후면이며 화살 발사체 그림을 별도로 날려 그리지 않았다.
- 쓰러지는 동안 키가 줄고 폭이 넓어진다. 모든 프레임의 바닥 접촉선은 y=120이고, 마지막 칸은 누운 몸의 지면 접촉선이다. 마지막 칸을 서 있는 인물 키로 다시 늘리지 않았다.

## 연결과 비교

게임용 파일명과 1/4/6/4칸 순서는 현재 시트를 유지했다. 기존 256×384칸은 D-081에 따라 288×384칸으로 바뀐다. 검토 페이지의 기존 시트는 원래 크기를 유지하면서 발 (128,352)을 새 발선에 맞춰 (16,8)만큼 이동해 표시한다. 새 그림의 크기가 기존과 다른 점을 그대로 비교할 수 있다.

Claude가 사용자 외형 확인 후 Game의 해당 시트를 교체하고 칸 크기·피벗을 반영한다. 검토용 초당 8칸은 게임 재생 시간의 확정값이 아니다. 노멀맵은 이번 카드의 지정 산출물에 포함하지 않았다.

## 확인 결과

- 15칸 모두 투명 RGBA, 알파 0/255, 바닥 접촉 마지막 행 y=119, 칸 경계 잘림 없음, 1~2픽셀 고립점 없음.
- 4종 게임 시트가 원본의 정확한 최근접 3배인 것을 픽셀 단위로 확인했다. 원본 규격과 프레임별 영역은 `validation.json`에 있다.
- Chrome에서 로컬 페이지를 열어 내장 이미지 12개(애니메이션 8개·전체 칸 4개)의 로딩과 재생·정지·한 칸 이동·뒤집기·속도 변경을 확인했다. 스크립트 오류 0, 너비 390픽셀에서 페이지 가로 넘침 없음. `review_validation.json`과 데스크톱·모바일 캡처를 제공한다.
- 생성 원안, 최종 접촉 시트, 검토 페이지의 데스크톱 캡처를 직접 확인했다.
- Game 파일 1,065개의 시작·종료 SHA-256이 일치했다. `source_hashes_before.json`은 읽기 전용 입력 확인 기록이다.

Unity 실행·Play·실제 게임 캡처·게임 연결·Git 쓰기는 수행하지 않았다. 지정 에셋 폴더와 검토 HTML, 루트 `CARD_RESULT.md`만 작성했다. 사용자 외형 검토와 Claude의 게임 연결·게임 내 확인이 남아 있다.

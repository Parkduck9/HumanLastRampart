최종 메인 생성 원본은 `codex_main_original.png`, 인물 보정 전 최초 생성본은 `codex_main_initial_original.png`로 구분하여 보존했습니다. 기존 `hero_back_idle.png`(256×384)를 직접 확인하고 은백색 머리·검은 제복·금색 장식·갈색 장화 특징을 최종 메인에 반영했습니다. 1024×1536 이동 시트와 배경은 용도가 달라, 배경을 캐릭터 시트 규격으로 나누지 않습니다.

## 제목과 한글 부제

영문은 요청한 **Human Last Rampart**를 `Human Last` / `Rampart` 두 줄로 배치합니다. 제목은 배경에 구워 넣지 않고 투명 SVG로 분리했습니다. 황동색 영문 세리프·크림색 한글 바탕 계열이며 시스템 대체 글꼴을 사용합니다. 글꼴 파일은 복사하거나 배포하지 않습니다.

- A: **인류의 마지막 성벽** — 기존 공통 UI 시안의 제목을 부제로 활용.
- B: **마지막 성벽을 지켜라** — 현재 MainMenuEntry 설명과 일치.

`source/codex_title_a.svg`, `source/codex_title_b.svg`는 편집 가능한 960×300 벡터 원본입니다. 배경과 별도 사용합니다. Unity에서 SVG 사용 방법·글꼴 고정·최종 래스터 출력은 승인 후 결정할 사항입니다.

## 기존 구성에 맞춘 기준

- `Game/Assets/_Project/UI/ScreenView.cs`: 공통 창 960×740, 중앙 정렬, 불투명 `#23302a`, 황동 `#d5b16b`, 본문 `#eee4cf`, 버튼 높이 60. 1920×1080에서 창 범위는 x=480~1440, y=170~910입니다.
- `Frontend/MainMenuEntry.cs`: 현재 중앙 창에 영문 제목·「마지막 성벽을 지켜라」·게임 시작·종료. 설정 버튼은 아직 이 코드에 없습니다.
- `Meta/ResultEntry.cs`: 성벽 피해·병력 손실·영웅 상태·다음. 검토 페이지는 해당 항목을 배치 확인용으로 표시합니다. 승리·패배 분기 연결을 구현한 것이 아닙니다.
- `Meta/PrepEntry.cs`, `PreparationPanel.cs`: 중앙 정비 메뉴, 모집·수리 창 범위 x=12~88%, y=7~85%. 상세 창에서는 넓은 배경이 가려지는 기존 구성을 전제로 합니다.
- `_HTML/codex_공통UI_화면시안_v1.html`: 올리브색·황동색·읽기 쉬운 창, 왼쪽 제목과 오른쪽 인물 방향.
- `_HTML/15_옥토패스식그래픽설계.html`: 도트 질감 입체 배경, 작은 인물, 겹친 원근·조명·약한 가장자리 흐림 방향. 원작 에셋은 사용하지 않았습니다.

중앙 창은 실제 코드 기준, 왼쪽 제목은 기존 HTML을 참고한 **배치 제안**입니다. 두 배치를 같은 페이지에서 비교하며 기존 코드가 왼쪽 메뉴로 바뀌었다고 해석하지 않습니다. 작은 한글은 도트로 만들지 않습니다.

## 규격과 재출력

최종 배경은 모두 불투명 PNG 1920×1080입니다. 생성 도구가 반환한 크기는 각 원본 파일에 보존하며 최종본은 PowerShell의 System.Drawing으로 규격만 맞춥니다. 1672×941 원본의 경우 16:9와의 비율 차이는 약 0.03%로, 가장자리 자르기 없이 전체 구도를 보존합니다. 팔레트 색 수와 도트 격자가 고정된 생산용 픽셀 아트는 아니며, 미니어처 분위기와 도트 질감을 확인하는 시안입니다.

저장소 루트에서 실행:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File Docs/References/codex_k027_v1/source/codex_build.ps1
```

이 스크립트는 이 카드 산출물의 최종 PNG·제목 SVG·검토 HTML만 다시 작성하며 Game/에 접근하지 않습니다. 생성 모델을 다시 호출하지 않습니다.

## 사용자 검토 후 남은 일

1. 배경 4장의 분위기, 인물 크기·복장, 승리와 패배의 차이 확정.
2. 한글 부제 A/B와 최종 제목 글꼴 확정. 장교는 기존 캐릭터 스프라이트의 동일성을 보증하는 합성이 아닌 새 시안입니다.
3. 현재 중앙 창 유지 여부 또는 왼쪽 제목 배치 채택 여부 결정.
4. 승인 후 별도 카드에서 Unity 가져오기·압축·필터·화면비 정책·결과 분기 연결 결정.
5. 사용자가 Play 및 실제 캡처를 수행한 뒤 가림·밝기·도트 밀도·가독성을 비교. 이번 카드에서는 Unity를 열지 않습니다.

## 이번 카드에서 확인한 범위

그림 4장의 구도를 직접 확인했고, 최종 PNG 4장 모두 1920×1080임을 검사했습니다. 검토 HTML 안의 PNG가 최종 파일과 바이트 단위로 일치하며 한글 부제 SVG 2안이 올바르게 내장됨을 확인했습니다. JavaScript 문법 및 모의 DOM을 이용한 배경 전환·부제 변경·왼쪽 배치 제한 검사를 통과했습니다. 이는 브라우저 렌더 검사와 다릅니다. 사용 가능한 브라우저가 없어 실제 HTML 표시·글꼴·모바일 배치·다운로드 클릭은 확인하지 못했습니다. Game 전체 파일의 작업 중 기준/최종 SHA-256 목록은 동일합니다.

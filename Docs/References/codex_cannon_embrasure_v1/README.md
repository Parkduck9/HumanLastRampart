# 대포 사격구 전용 성벽과 앞난간 (T-CX-043)

사용자 방향: 활·총 병사는 성벽 위 통로/난간 자리에서 싸우고, 대포는 난간 사이로 포신을 내밀어 쏜다. 이번에는 같은 돌/도트 계열의 대포 전용 넓은 사격구를 새 정적 에셋으로 제작한다. A 기본 회색 성벽을 재질 기준으로 삼았으며 기존 B/C 시안을 폐기하거나 최종 성벽 선택으로 확대하지 않는다.

## 새 정적 에셋

| ID | 구성 | 용도 |
|---|---|---|
| wall_cannon_bay | 가운데를 넓게 낮춘 U자 사격구와 성벽 본체 | 일반 병사용 성벽 사이에 대포 전용 구간으로 검토 |
| parapet_cannon_front | 낮은 턱 + 좌우 높은 돌 난간, 가운데 열린 영역 | 대포 그림 앞쪽에 겹쳐 차체는 일부 가리고 포신은 틈으로 보이게 하는 별도 레이어 |

각 에셋 1024×512 RGBA 1칸 정적, 투명 여백과 중앙 사격구를 유지한다. 원본/포장/JSON을 별도 보관한다. 절차로 벽돌을 새로 그리거나 포신을 지우지 않고 imagegen 내장 도구로 새 정적 그림을 생성한다. 포장에서는 전체 그림 최근접 축척/배치만 수행한다.

## HTML 검토

_HTML/codex_대포사격구성벽_v1.html: 넓은 사격구와 대포를 겹쳐 좌·중앙·우 조준, 포탄 방향, 앞난간 표시/숨김을 비교한다. 앞난간과 대포 높이를 조정해 가림을 확인할 수 있다. 기존 병사 후면 시안을 통로 양쪽에 참고 배치한다. 기준선과 조정값은 시각 검토용이며 물리 충돌·포구 좌표·Unity 카메라 수치를 확정하지 않는다.

전체 성벽 모듈과 별도 앞난간은 각각 단독으로 내려받을 수 있다. HTML의 겹침 예시는 두 에셋의 게임 제작 레이어 분리를 제안하는 자료다. 실제 게임에서 A/B/C 벽과 경계/발판을 맞추고 좌우 조준 한계·통로와 바퀴 폭·포구점·병사 배치를 검토해야 한다. Game/Art/Combat과 이전 에셋은 변경하지 않는다. Unity Play 미실행, 게임 연결은 Claude 담당이다.

프롬프트·생성 경로 generation.json, 파일 검증 qa.json, HTML 확인 캡처 browser_review.png.

## 확인 결과

새 PNG 2개는 중앙 상부 사격구가 실제 투명한지, RGBA/1칸 규격/포장 경계/원본 보존/저장 픽셀·내장 자료·JS 구문이 맞는지 확인했다. 브라우저에서는 재사용 7개 포함 총 9개 그림 준비 후 좌/중앙/우 조준 3회 발사, 앞난간·병사 가림 토글, 대포·난간 높이 및 크기 조절, 초기화 동작을 확인했다. 검사 콘솔 오류 0, 기본 창 가로 넘침 없음. 표시용 에셋 카드 2개 로드 확인. file: 직접 실행과 Unity Play는 검사하지 않았다.

합성 화면의 중앙 발판은 새 성벽 원본의 낮은 석재 발판 면을 잘라 표시한 참고 배치다. 난간 전체와 낮은 턱을 대포 뒤에 그리고 좌우 기둥 영역만 앞 가림으로 다시 그려 포신을 가리지 않게 했다. 이 영역 구분은 HTML 렌더링용 제안으로, 새 PNG를 지우거나 덧칠한 것은 아니다. 병사 발판과 통로의 실제 높이·가림 순서는 게임 카메라에서 후속 확인한다.

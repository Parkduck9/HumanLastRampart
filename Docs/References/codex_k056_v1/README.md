# K-056 약 3등신 시험 그림 v1

사용자 확정 전 비교 자료(D-064). Game에는 연결하지 않았다. 제작 도구는 내장 `image_gen`이며 최종 프롬프트는 `prompts.json` 및 `prompts_run_revision.json`에 보관했다. 기존 인물을 참고해 새 그림을 생성하고 실제 기존 색으로 규격화했다. 실물 참고 사진은 이번 대화/카드 입력에 없어 사용자 명시 비율(머리 약 1/3)을 기준으로 했다.

## 먼저 열 파일

- `../../../_HTML/4_그림_캐릭터/codex_K-056_3등신시험_v1.html`: PNG를 모두 내장한 오프라인 검토 페이지. 기존/신규/3등신 도식의 동일 키 비교, 화면 높이 13% 비교, 동작 재생/정지/이전/다음/속도 선택.
- `all_frames_256.png`: 15칸 전체 보기. 행과 열 번호는 아래 표와 같다.
- 파일명 끝 `_64.png`는 원본 칸 64×96, `_256.png`는 게임용 칸 256×384이다. 둘은 동일 그림의 최근접 4배 관계다.

## 규격과 색

- 원점은 칸 왼쪽 위. 발 기준 원본 (32,88), 게임용 (128,352). 실제 발 픽셀은 각각 y=87 / y=351까지 있고 그 다음 격자선이 발 기준이다.
- 모든 인물 키 48점 / 게임용 192점. 머리와 머리카락 약 15~17점, 몸통·다리 합 약 31~33점. 칸 안에 여백을 남겼다.
- 투명도는 0 또는 255만 사용한다. 인물 외곽의 가장자리 픽셀을 팔레트의 어두운 색으로 맞췄다. 작은 장비 끝이나 가는 선은 도트 단위로 단순화된다.
- 재질별 주 명암을 3~4단계로 제한하는 방향이며, 인물 전체의 색 수는 그보다 많다. 궁수 19색·주인공 21색 이하의 고정 팔레트에서 사용한다. 실제 목록은 `archer_palette.txt`, `hero_palette.txt`이며 모두 원본 시트에서 실제 존재하는 RGB를 뽑았다. 가장 가까운 색으로 배정한 뒤 반투명·새 RGB를 만들지 않았다.
- 궁수 팔레트 출처: `Game/Assets/_Project/Art/Characters/Static/archer_static.png`, `Fire/archer_fire.png`.
- 주인공 팔레트 출처: `Game/Assets/_Project/Art/Characters/Hero/hero_back_idle.png`, `Hero/hero_walk_run_grid.png`.
- **중요:** 현재 저장소의 정적 기존 인물은 실제 불투명 영역 높이가 약 300점이다(사용자 설명의 약 210점과 다름). 새 게임용은 요청대로 192점이므로 동일 칸·동일 게임 배율에서는 기존 키의 약 64%가 된다. 검토 페이지는 양쪽을 같은 키로 맞춘 비교다. 실제 게임에서 둘을 같은 키로 비교하려면 Claude가 별도의 배율을 적용해야 하며, 이번 작업은 배율·코드를 수정하지 않는다.

## 내보낸 시트의 칸 순서

아래 번호는 0부터 시작하며 행은 위에서 아래, 열은 왼쪽에서 오른쪽이다. 각 파일은 `_64`와 `_256` 두 크기로 제공한다.

| 파일명 앞부분 | 배치 | 칸 순서 |
|---|---|---|
| `archer_back_idle` | 1×1 | 후면 서기 |
| `archer_back_walk4` | 4×1 | 후면 걷기 0 → 1 → 2 → 3 → 0 |
| `archer_fire4` | 4×1 | 준비 → 반쯤 당김 → 끝까지 당김 → 놓기 |
| `archer_fire6_compat` | 6×1 | 준비 → 반쯤 당김 → 끝당김 → 끝당김 → 놓기 → 놓기 |
| `hero_back_idle` | 1×1 | 후면 서기 |
| `hero_side_run4` | 4×1 | 왼쪽 달리기 0 → 1 → 2 → 3 → 0 |
| `hero_front_idle` | 1×1 | 정면 서기 |
| `hero_layout_preview` | 4×4 | 아래의 현재 Game 행 위치에 요청한 동작만 배치. 빈 칸은 투명 |
| `all_frames` | 5×3 | 0행: 궁수 서기·걷기4 / 1행: 궁수 사격4·주인공 정면 / 2행: 주인공 후면·달리기4 |

### 기존 시트와의 대응

- 궁수 기존 정적은 1칸, 기존 사격은 가로 6칸이다. 요청은 사격 4칸이므로 기본 4칸과 6칸 대응본을 모두 제공했다. 6칸 대응본의 놓기는 **4번 칸**(다섯 번째)이며 기존 사격 해석과 맞춘 것이다. 대응본은 4포즈를 복제한 6칸이지 새로운 6포즈가 아니다.
- 기존 궁수 후면 걷기 시트는 없다. `Run/archer_run.png`는 옆 달리기여서 요청한 후면 걷기의 칸 순서 근거로 쓰지 않았다. 신규 후면 걷기는 왼쪽에서 오른쪽 4칸으로 문서화했다. 페이지의 기존 후면 걷기 비교는 기존 정적 그림 고정이다.
- **현재 Game의 주인공 시트** `hero_walk_run_grid.png`는 4열×4행, 0행 후면 걷기 / 1행 왼쪽 걷기 / **2행 왼쪽 달리기** / 3행 정면 걷기다. 과거 자료의 append 시트(달리기 3행)와 혼동하지 않는다.
- `hero_layout_preview`는 0행 0열에 후면 서기, 2행 0~3열에 왼쪽 달리기, 3행 0열에 정면 서기만 넣은 **위치 검토본**이다. 요청하지 않은 걷기 칸이 비어 있으므로 기존 전체 주인공 시트를 통째로 대체하면 안 된다. 별도 서기 1칸과 달리기 4칸 파일을 우선 사용한다.
- 오른쪽 달리기는 왼쪽 시트를 좌우 뒤집는 기존 방식에 대응한다. 이번 시안은 오른쪽 별도 그림이나 게임 연결을 제작하지 않았다.

## 원안과 최종 제작 과정

1. `generated.png`: 첫 생성. 3등신보다 길쭉한 몸·배경 잔여가 있어 제외.
2. `generated_v2.png`: 궁수 9칸·주인공 앞/뒤 서기 채택. 이 파일 안의 달리기는 제외.
3. `generated_run.png`: 달리기 별도 생성. 팔 교대가 약해 제외.
4. `generated_run_v2.png`: 달리기 팔 교대 수정본 채택. 다리 위상·접지 자연스러움은 아래의 남은 검토 사항이다.
5. `build_assets.ps1`: 생성된 전체 포즈를 칸별로 잘라 48점 키로 최근접 축소, 인물별 팔레트 배정, 외곽 한 점 정리, 64×96 배치, 정확한 최근접 4배 확대. 팔다리를 잘라 재조립하지 않았다. PowerShell 5에서 한글 인코딩 문제를 피하려면 `Get-Content -Raw -Encoding UTF8`로 읽어 `Invoke-Expression`으로 실행한다.
6. `frame_00`~`frame_14`: 각 최종 포즈. 전체 보기의 행 우선 순서와 같다. `manifest.json`에 크기·팔레트 수·원본 해시·조합 순서를 기록했다.
7. `build_review.py`: 이미지를 바꾸지 않고 최종 PNG와 기존 PNG를 검토 HTML에 내장한다.

## 확인 결과와 한계

- `validate.py` 실행: **137개 통과**. 인물별 기존 팔레트 색 포함, 새 RGB 없음, 투명도 이진, 칸 크기, 15칸 모두 키 48·발끝 기준·여백, 최근접 4배 바이트 일치, 4칸 동작별 서로 다른 그림, 6칸 대응 순서 확인.
- `check_review.cjs`: 최소 화면 모형에서 JS 선택·재생·일시정지·수동 이동·첫/끝 순환·동작 변경·내장 이미지 수를 검사한다. 결과는 `qa_review_logic.json`에 기록한다. 실제 화면 렌더링 검사가 아니다.
- 최종 전체 시트 PNG를 직접 열어 외형과 큰 잘림을 확인했다. 연결 가능한 브라우저가 없어 실제 HTML 렌더링·버튼 클릭·작은 창 줄바꿈·캡처는 **미검증**이다.
- Unity는 열거나 실행하지 않았다. Game 변경 없음. 실제 배율·UV·프레임 시점·발 접지·게임 내 조명·노멀맵·화면 가독성은 미검증이다.
- 특히 달리기의 다리 교대가 약하고 공중/접지 단계 구분이 충분하지 않을 수 있다. 이번 판은 비율·점 크기 비교를 먼저 위한 시험 그림이며, 동작 자연스러움을 최종 승인으로 간주하지 않는다.
- 얼굴·머리·옷은 같은 사람을 유지하는 방향으로 만들었으나 생성 과정에서 견장·멜빵·활/화살통 위치와 세부가 달라질 수 있다. 궁수 사격은 왼쪽을 향한 후면 사선이며 앞·뒤 서기와 장비 읽힘의 일관성도 사용자 검토가 필요하다.
- 질문/결정 대기: 이 비율·점 크기를 전체 캐릭터에 확대할지, 현재 외형을 유지한 채 동작부터 추가 보완할지. 실제 참고 사진과의 최종 대조는 사진을 볼 수 있는 다음 검토에서 진행한다.

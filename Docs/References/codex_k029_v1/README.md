## 규격과 목록

**지도에서 5m = 32화소, 1m = 6.4화소.** 기존 Game 환경 질감의 1m = 32화소와 다르다. 지도용으로 별도 사용해야 한다. 각 칸은 32×32 RGBA PNG, 중심 피벗 (16,16), Unity 아래 원점 기준 (0.5,0.5) 제안. 점 필터·무압축·sRGB·격자/아이콘 Clamp를 제안하며 임포트 설정은 바꾸지 않았다.

## 레퍼런스와 제작

읽은 기준은 FirstRead → RULES → DECISIONS → CONTRACTS, 원본 협업 폴더의 Claude outbox·tasks 및 Codex tasks, K-024·K-025 README·규격, Game/Art/World README다. 원본 `.git/HEAD`는 develop, 카드 가지는 card/K-029였다. 협업 기록은 읽기만 했다.

Game 환경 풀·흙·회색 석재 계열, K-024의 함정 전후 상태 의미, K-025의 수직 윗면 나무·바위와 회녹색 색감을 참고했다. K-024의 기울어진 실물 함정은 지도에 그대로 축소하지 않고 기호 2종으로 구분했다. K-025 윗면 4장의 사본을 source/에 보존했다. 나무·바위 칸은 배치 대상 구역이며 수관의 실제 크기나 충돌 크기를 확정하지 않는다.

내장 image_gen으로 지형 3열×2행 원안과 투명 성 둘레 원안을 생성했다. source/에 원안을 보존했다. 지형은 바깥 경계선을 피하여 각 504×504 영역을 자르고 최근접으로 32×32로 줄였다. 풀과 언덕은 공통 바깥 한 화소 띠를 사용한다. 흙은 자체 좌우·상하 경계를 일치시켰다. 길은 생성 흙과 풀을 폭 14화소 기하 마스크로 조합한다. 반투명 UI 겉칠과 지도 기호는 간단한 기하 도형으로 제작했다.

`build.py`는 원안·보존 사본으로 크기 조정·분할·조합, manifest·비교판·독립 HTML을 재생성한다. `source/review.template.html`이 HTML 편집 원본이다. Pillow가 필요하다. Game 에셋·meta는 만들지 않았다.

## 반복과 무작위 조립의 범위

풀·흙·언덕의 동일 타일 좌우/상하 끝 화소 일치를 확인했다. 풀 2종과 언덕은 같은 경계 띠를 사용하므로 섞을 수 있다. 길의 맞닿은 연결 비트가 같은 모든 조합에서 경계가 일치한다. 내부 무늬가 자연스럽게 이어지는지는 사용자 외형 검토가 필요하다.

언덕은 **한 칸 안의 독립 둔덕**이다. 높이 3단계는 시각 구분이며 실제 미터 높이·충돌·설치 불가 판정은 정의하지 않는다. 여러 칸에 걸쳐 하나로 이어지는 산비탈/등고선 연결 세트는 아직 없다. 여러 칸 크기의 언덕이 필요하면 중심·경사·모서리 연결 타일을 후속 제작해야 한다.

HTML은 매번 풀·독립 언덕·소품을 섞고 성을 중앙에 원위치 조립한다. 길은 남북으로 배치하고 나머지 16종은 반복 선택에서 확인한다. 함정 두 위치와 터진 자리 하나는 상태 비교를 위한 고정 예시다. 실제 새 게임 지형 생성기·설치 규칙·구매·저장·전투 동작은 구현하지 않았다.

## 수행한 확인

- `verify.py`: PNG 규격·해시·HTML 내장 바이트, 지형 불투명도와 반복 경계, 길 연결 모든 쌍, 격자 반투명도, 성 원위치 복원 등 **564항목 통과**. qa/verification.json.
- `verify_html.cjs`: JS 구문 및 최소 DOM 모형에서 로드·갤러리·새 지형·칸 선택·방향키·확대·겉칠 전환·반복 선택 등 **10항목 통과**. qa/html_model.json.
- 생성 원안 2장과 최종 비교판·합성 지도를 직접 열어 육안 확인했다. 이 PNG는 브라우저 캡처가 아니다.
- Game 파일 목록과 SHA256 전후 일치. qa/game_before.sha256, game_after.sha256.
- 브라우저 연결 조회 결과 apps/browsers가 모두 비어 있었다. 실제 렌더링·반응형·콘솔·file 주소 조작은 **미검증**.
- Unity 실행·Play·실제 캡처·노멀맵·게임 배치·밤 시인성은 **미검증**. Git 쓰기와 협업 기록 변경은 하지 않았다.

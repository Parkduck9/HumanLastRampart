## 지형 그림 규격안

| 종류 | 지도 칸 | 지도 칸의 범위 | 전투 판 |
|---|---|---|---|
| 직선 토벽 · 짓는 중/완성 | 64×32 | 10×5m | 각 320×96 |
| 모서리 토벽 · 짓는 중/완성 | 64×64 | 10×10m | 각 320×160 |
| 작게 쌓은 언덕 | 32×32 | 5×5m | 160×96 |
| 크게 쌓은 언덕 | 64×64 | 10×10m | 320×160 |
| 쓰러진 나무 더미 | 32×32 | 5×5m | 160×80 |
| 바위 더미 | 32×32 | 5×5m | 160×112 |

지도는 중앙 피벗, 전투 판은 `(폭/2, 높이-8)` 제안이다. 전투 판은 32px/m로 볼 때 캔버스 폭 5m 또는 10m이며, 지도와 전투의 캔버스 가로 범위를 맞췄다. 투명 여백과 종횡비 보존 축소 때문에 실제 내용 폭은 캔버스보다 작다. 표의 범위는 점유 판정·통행·충돌 크기를 뜻하지 않는다. 전투 이미지의 높이는 경사 투영과 지면 깊이를 포함하므로 토벽·언덕의 실제 높이로 환산하지 않는다.

저장 형식은 투명 PNG다. 원안의 알파를 유지하고 실체 경계 검출에만 알파 128을 사용했다. 후처리는 알파 경계 자르기·최근접 축소·투명 여백 배치·시트 합성이다. RGB 덧칠·키 색 제거·배경 추출은 하지 않았다. 투명 픽셀에도 배경색 RGB가 남을 수 있어 알파를 무시하는 뷰어에서는 원안 후광이 보일 수 있다. 알파 합성한 최종 비교판을 기준으로 본다.

## 병사 작업 6종

궁수·총병 각각 삽질, 흙 나르기, 통나무 나르기 4칸이다. 시트는 **1024×384, 4열×1행**, 낱칸은 **256×384**, 제안 피벗 `(128,352)` / Unity 아래 원점 `(0.5,0.083333…)`다. 5칸/초는 HTML의 비교용 기본값이다.

삽질은 준비→땅 누르기→흙 뜨기→던지기, 나르기는 물건을 든 제자리 걸음 순서다. 흙 나르기는 작은 나무 바구니, 통나무 나르기는 어깨에 나무 한 개를 받친 모습이다. 작업 중 활·총은 생략한 시안이다. 기존 제복 정체성을 참조했지만 생성 도구가 새로 그렸으므로 원래 옷의 픽셀 위치까지 보존한 편집은 아니다.

처음 12칸 원안의 삽질 행은 칸 경계를 넘는 도구와 인물 조각이 있어 최종 채택하지 않았다. 삽질은 넓은 4칸 원안을 다시 생성했다. 나르기는 보정한 12칸 원안의 2·3행을 썼다. 각 원안 안에서는 공통 배율로 축소하고 프레임마다 바닥을 352에 맞췄다. 나르기 두 동작은 같은 배율, 삽질은 별도 공통 배율이다. 정확한 몸 중심·발·손과 도구 접점·전진량을 설계하거나 보정한 것은 아니다.

## 미해결 외형과 연결 사항

- 지도 모서리 토벽은 짓는 중과 완성의 L 방향이 다르다. 전투 판과 지도 판도 자동 접속용 투영쌍이 아니다. 시안 검토 후 동일 방향의 접속 전용 원안 제작이 필요하다. 직선 끝·모서리 이음, 90도 회전 시 광원, 반복 길이는 미검증이다.
- 지도용 나무의 단면 노출은 보정했으나 흙 능선과 바위 명암에는 옆면 인상이 남을 수 있다. 작은 32px 바위/나무 실루엣의 구별, 언덕 크기 차이는 검토 페이지에서 확인할 사항이다.
- 병사 복장 테두리 두께·옷자락·총병 어깨판과 가죽끈은 프레임 사이 조금 달라진다. 기존 병사 복장과 최종 일치 여부, 손과 삽·바구니 접점, 통나무 무게감·걷기 주기·키 차이는 사용자 검토가 필요하다.
- 토벽 완성도와 높이, 언덕 경사, 더미 크기와 옮김 가능 표현은 제안이다. 비용·시간·작업 인원·이동 규칙·적 유도·파괴 조건·전투 성능을 정하지 않았다.
- 노멀맵·빌보드·그림자·메시·충돌·내비게이션·게임 코드·Unity 임포트 파일은 만들지 않았다. 문서용 시안이므로 새 `.meta`도 없다. 채택 뒤 Claude가 연결하며 에셋과 meta를 함께 관리해야 한다.

## 실제 확인 결과

- `qa/image_checks.json`: 최종 지형 16장·동작 시트 6장의 크기, 알파 0 여백, 알파 128 초과 실체, 외곽 잘림 검사 22종 통과. `visiblePixels`는 알파 128 초과 화소 수이며 `partialAlphaPixels`와 겹칠 수 있다.
- `qa/verification.json`: 최종 그림 22종의 HTML 내장 바이트·규격 일치, 외부 src/href 없음, 템플릿 표시자 없음 확인. 기존 기준 `qa/game_before.json`과 Game 파일 **594개** 해시 비교 결과 변경 0개. `qa/game_after.json`에 후값을 보관했다.
- `qa/runtime_checks.json`: V8에서 `source/verify_runtime.mjs`의 최소 DOM/Canvas 모형으로 페이지 스크립트를 실행해 로드·선택·확대·프레임·재생 17항목 통과. 실브라우저와 구별한다. 처음 모형 검사의 임의 그리기 횟수 조건을 실제 예상 횟수(지도 9회+프레임 11회)로 고쳐 재검사했다.
- 생성 원안과 최종 밝은 배경 비교판을 직접 열어 확인했다. 실제 브라우저 목록이 비어 있어 브라우저 렌더링·콘솔·반응형·file 직접 실행은 미검증이다. Unity·Play·실제 캡처도 수행하지 않았다.

PowerShell 5에서 한글 스크립트를 읽도록 `.ps1`은 UTF-8 BOM으로 저장했다. 첫 실행의 인코딩 오류와 편집 중 중복 변수 구문 오류는 수정 후 재생성했으며 위 결과는 최종 성공 실행 기준이다.

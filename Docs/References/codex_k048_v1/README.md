## 실측과 비율

실제 파일은 `Game/Assets/_Project/Art/Battle/Resources/BattleArt/` 아래에 있다. 카드 지시의 `Combat/Battle/Resources/BattleArt/` 경로는 없었다. 원본을 읽기만 했다.

알파128 초과 픽셀의 최소 경계로 측정했다. 좌표는 왼쪽 위 원점이며 오른쪽·아래 경계는 제외한다. 정확한 파일·칸별 좌표는 `measurements.json`에 있다.

정지 대포병은 실제로300px였다. 사용자 요청의 새 병사210px를 유지하려고 비교 묶음의 정지 병사와 설치 대포를 모두0.7배로 표시한다. 정면 대포345×320에0.7을 곱하면241.5×224px이므로 운반 대포는242×224px로 반올림했다. 비율은 폭242/210=1.1524, 높이224/210=1.0667이다. K-043의241×116px와 비교하면 폭은 거의 같고 높이는약1.93배다.

이것은 그림 원본의 픽셀 비율이다. 실제 게임 화면의 화면 배율·물리 크기는 실측하지 않았다. K-016 반동 그림과3방향 그림의 원본 크기도 서로 다르므로 어느 쪽이 현재 게임에서 어떤 크기로 표시되는지는 이번 카드에서 확정하지 않는다.

## 보행과 접지

내장 imagegen 원안을 세 차례 제작했다. 최종 원안은 다리 명암으로 왼발(어두움)·오른발(밝음)을 구분한다. 원안 열을1,2,6,4,5,3 순서로 정리해 첫 세 칸은 왼발 디딤, 다음 세 칸은 오른발 디딤이 된다. 6칸의 끝에서 내민 왼발이 다음1칸에서 디딘다.

각 칸의 실제 부츠 아래 두 줄을 측정해 디딘 발 x를84→124→164 / 84→124→164px에 놓았다. 칸 전환마다 왼쪽40px 이동하므로 왼발 디딤의 세계 x는84/84/84, 오른발은-36/-36/-36px이다. 양 병사 모두 저장된 PNG를 다시 읽어 이 수치를 검사했다. 기록 좌표만 비교한 검사가 아니다.

기본6칸/초, 한 주기240px 이동, 바퀴 각도=-이동거리/71이다. 바퀴는 같은 PNG의 원형 부분을 회전 합성한다. 디딘 발이 한 칸을 유지하는 동안 미끄러지지 않도록 이동과 회전을 칸 경계에서 함께 갱신한다. 이 페이지는 연속 이동 보간을 하지 않는다. 따라가는 시점은 지면 눈금이 오른쪽으로 가며, 고정 시점은 분대가 왼쪽으로 간다. 고정 시점은 세 주기 후 위치를 초기화한다.

몸을 기울이는 무게감과6→1의 최종 자연스러움은 사용자 외형 검토 대상이다. 게임에서 연속 이동을 쓰면 별도의 발 고정 처리가 필요할 수 있다.

## 점화

커진 대포에 맞춰 새 점화 원안을 세 차례 만들고, 적당한 길이의 막대를 머리보다 높이 올리는 원안을 채택했다. 불씨와 인물을 같은 비율로 정리하고 발을352px에 유지했다. 4번째 칸의 불씨 아래 밝은 부분 (66,133)이 대포 도화선 (346,133)에 닿는다. 병사의 배치 x만 조절하며 발 높이를 움직이지 않는다. 검토 장면의 대포 왼쪽 위가(380,0)이므로 병사 칸 왼쪽 위는(660,0), 접점은(726,133)이다.

0.50초 접촉·점화 → 1.50초 발사로 정확히1초 대기한다. 1.50~2.10초 포구 연기6칸을10칸/초로 표시하고3.20초마다 반복한다. 연기는 K-043에 보관된 K-016 사본을 재사용했다. 실제 게임의 발사 판정은 구현하지 않았다.

## 제작 자료와 재현

- `prompts.json`, `generation.json`: 실제 내장 imagegen 프롬프트8개, 채택/미채택 대응과 이유.
- `crew_source.png`, `cannon_source.png`, `ignite_source.png`: 채택 원안. `*_candidate_*.png`: 비교 과정에서 미채택한 원안5개.
- `BitmapTools.cs`, `build.ps1`: 칸 분리·알파 경계 실측·최근접 배율 정리·부츠 접지 정렬·고립 잔여 픽셀 제거·시트 포장·내장 HTML 생성. 보행 인물의 연결된 주 성분 알파는 보존한다.
- 대포 원안 외곽1177×1022를242×224에 맞춰 가로0.2056075배·세로0.2191781배로 정리했다. 실측 외곽 비율을 맞추기 위한 약6.6%의 비율 보정이다. 설치 그림은 정면, 새 그림은 옆모습이라는 투영 차이가 있으며 같은 무기로 읽히는지와 바퀴 형태는 검토가 필요하다.
- `installed_aim3.png`, `installed_recoil3.png`, `installed_crew.png`, `previous_cannon.png`, `muzzle_smoke.png`: 읽기 전용 원본의 사본. Game/ 파일을 수정하지 않았다.
- `compose.ps1`: HTML과 같은 좌표를 쓰는 정적 비교·보행6칸·점화 접점·모아보기. 브라우저 캡처가 아니다.
- `verify_assets.ps1`, `verify.mjs`: PNG 실측90항목, HTML의 Node VM 모형63항목 검사.

Windows PowerShell에서 이 폴더의 `build.ps1` → `compose.ps1` → `verify_assets.ps1` 순서로 실행한다. 보관한 원안으로 다시 만들 수 있으며 Python·Unity가 필요 없다. Node에서 `verify.mjs`의 `verify(자료폴더절대경로,HTML절대경로)`를 호출하면 `qa_html.json`이 생성된다.

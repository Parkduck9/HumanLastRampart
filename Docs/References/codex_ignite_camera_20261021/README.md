# K-086 v5 실제 카메라 점화 시험

- 작성: Codex · 2026-10-21
- 상태: **부모 작업에서 Unity PlayMode 1/1 통과·실제 카메라 사진 6장 저장. 시각 접촉은 미완료**.
- 대상: `PlayProbe.IgniteContactSixFrames`.

## 완료 조건과 범위

1. 검토 폴더의 `game/cannon_crew_ignite6.png`를 2592×384로 읽고, 실제 이름 기반 로더가 여섯 칸과 발 위치 288·360을 선택하는지 검사한다.
2. `game/cannon_recoil_fuse.png`는 기존 대포와 같은 768×256 세 칸 반동 시트여야 한다.
3. 이야기 단계에서 대포병 정의의 점화 시트만 메모리에서 바꿔 실제 전투 뷰를 생성한다. 대포 그림도 해당 뷰의 `_MainTex`만 메모리에서 바꾼다. Game 그림 파일·정의 에셋은 저장하거나 수정하지 않는다.
4. 준비 상태를 유지하고 일시 정지한 채 지도를 닫는다. 첫 대포 위치로 주인공의 성벽 방향과 가로 위치만 옮긴다. **BattleCameraRig A의 거리 3m, 높이 2.1m, 각도 24도, 화각 40도를 유지한다.** 확대 촬영이나 별도 정투영 사진기가 아니다.
5. 실제 `sFuse` → `IgnitePose` → `RefreshSoldierInstances` 경로에서 1~6번 칸을 선택하고, 그리기 버퍼의 값과 보이는 상태를 검사한다. 4번도 같은 경로로 확인한다.
6. 기존 ProbeShooter로 1920×1080 장면 사진 여섯 장을 저장한다. 촬영 전후 전투 시간이 같은지 검사한다.
7. 원래 정의·재질 블록·일시 정지·지도 상태·시간 설정을 finally에서 복원하고 Boot로 나가 임시 뷰를 해제한 뒤 임시 텍스처를 파괴한다.

## 기술 판정과 시각 판정의 구분

시험 통과는 크기·피벗·실제 여섯 칸 선택·전투 정지·텍스처 연결의 증거다. **도화선에 횃불이 시각적으로 닿는지, 3→4번에서 횃불 길이가 일정한지, 동작이 자연스러운지는 사진을 직접 판독해야 한다.** 이 시험에 접촉 성공 자동 판정은 넣지 않았다.

새 그림이 없거나 크기가 맞지 않거나 그래픽 장치가 Null이면 실패한다. 기존 그림으로 대체해 성공을 기록하지 않는다. 적을 사격하거나 실제 전투 승패를 재는 시험도 아니다.

실행은 부모가 수행했다. 이 보고서 작성 하위 작업은 Unity를 실행하지 않았다. 시험은 크기·피벗·여섯 칸의 실제 그리기 버퍼 값 80~85·텍스처 연결·전투 시간 0 유지·사진 저장을 확인했다. **전체 시험 모음 통과를 뜻하지 않으며 실제 접촉을 자동 검증하지 않았다.**

사진 원본 3·4·5번을 직접 열어 확인했다. 4번에서 횃불 불꽃은 대포 뒤 큰 원형 뚜껑 부근에 있고, 새 도화선 고리는 그보다 위에 있다. 1920×1080 원본에서 고리 부근 y≈580, 불꽃 중심 y≈617로 보인다. 이는 육안의 대략적인 화면 좌표이며 정확한 월드 간격이나 보정량 측정이 아니다. 따라서 **실제 카메라 접촉은 미완료**로 기록한다. 3→4에서 팔·몸의 자세가 바뀌는 것도 확인되며, 횃불 길이와 동작 자연스러움은 원본 연속 비교로 계속 검토해야 한다.

원인 후보는 대포 그림의 바깥쪽 배치와 병사 발 위치의 깊이 차이 때문에 2D 비교안과 실제 원근 투영의 높이가 달라지는 것이다. **투영 계산 전에는 원인이나 보정량을 확정하지 않는다.** 카메라·에셋의 임의 변경으로 해결했다고 기록하지 않는다.

촬영 로그상 카메라 위치는 `(-12, 6.1, 16)`, 회전 `(24, 0, 0)`, 화각 40도다. 실제 카메라 시점과 렌더러를 사용했으나, 그림은 테스트 메모리에만 교체했다. Game PNG·정의 에셋 적용은 아직 하지 않았다. 전투 시간은 고정되어도 연기 등 실시간 표시 효과는 사진 사이에 달라질 수 있다.

# K-089 정비 마당 파노라마

[검토 페이지](../../../_HTML/6_그림_화면/codex_K-089_정비마당배경_v1.html)는 서버 없이 직접 연다. 그림·코드·스타일을 모두 내장했다. 장소 바로 보기, 화면 좌우 이동, 배율, 바닥을 눌러 영웅 놓기, 앞뒤 이동 재생, 통행 마스크·가림 물체 강조·인물 가림 전환을 제공한다. 현재 게임 배경과 새 구도를 함께 비교한다.

## 깊이와 영웅 크기

최종 사용자 결정의 **6~10m 깊이**를 따라 8m로 제작했다. 브리프의 앞선 2~4m 예시는 이 값으로 대체했다. 실제 이동은 좌우뿐 아니라 위아래로 가능하게 할 것을 전제로 한다.

| 기준 | 가까운 선 | 먼 선 |
|---|---:|---:|
| 화면 y, 위에서 아래로 | 1020 | 480 |
| 가까운 선으로부터 거리 | 0m | 8m |
| 가로 방향 화소/m | 약 128.824 | 약 64.412 |
| 깊이 방향 국소 화소/m | 135 | 33.75 |
| 기존 73px 영웅 원본 배율 | 3배 | 1.5배 |
| 288×384 게임 시트 기준 배율 | 1배 | 0.5배 |
| 영웅의 보이는 키 | 219px | 109.5px |

좌표 원점은 그림 왼쪽 위, x는 오른쪽, y는 아래쪽이다. 보이지 않는 지평선 제안값은 y=-60이다. 실물 영웅 키를 1.7m로 가정해 화소/m를 계산했다. 1.7m는 이번 연결용 보정 가정이며 새 사용자 결정이 아니다.

가까운 선으로부터 멀어지는 거리 `d`(0~8m), 바닥 가로 좌표 `X`(m)에 대해 다음 식을 쓴다.

```text
q = 1 + d / 8
화면 x = 1920 + (219 / 1.7) × X / q
화면 y = -60 + 1080 / q
영웅 원본 배율 = 3 / q

d = 8 × (1080 / (화면 y + 60) - 1)
X = (화면 x - 1920) × (1 + d / 8) / (219 / 1.7)
```

`manifest.json`에는 이 식과 일치하는 약 30도 하향 카메라의 초점 거리·높이·주점도 적었다. 생성 그림의 모든 건물과 돌을 실측해 복원한 카메라는 아니다. 연결할 때는 고정 투영을 유지하고 화면 잘라 보기로 가로 이동한다. 인물은 화면을 향하는 평면 그림을 가정한다. 원근 변환 후 통행 마스크를 검사하면 위아래 이동에 필요한 거리와 크기를 일관되게 재현할 수 있다.

먼 선과 가까운 선은 전역 깊이 한계다. 양쪽 앞담·적재물 때문에 모든 x에서 같은 깊이까지 걸을 수 있는 것은 아니다. 실제 통행은 마스크를 따른다. 마스크에는 밑면 충돌에 약 0.2m 여유를 이미 더했다. 같은 여유를 엔진에서 다시 더하지 않는다. `collision_polygon_px`는 물체 밑면의 제안 윤곽이며, 마스크는 앞담·적재물도 함께 막는다.

좌표와 범위는 연결용 제안값이다. 범위 안 모든 점과 각 장소의 세로 접근선이 통행 마스크 위에 있음을 검사했다. 계단은 바닥 상호작용 지점에서 다음 전투로 나가는 장소이며 계단 자체를 걷는 통행 마스크는 포함하지 않았다.

## 가림 레이어 연결

배경에도 같은 물체가 남아 있다. 별도 PNG는 영웅이 물체 뒤에 갔을 때 영웅 위에 같은 물체를 다시 그리는 용도다. 따라서 정렬이 맞으면 배경과 이음매가 생기지 않는다. 별도 레이어를 숨기는 것은 배경 속 물체를 지우는 기능이 아니다.

1. 배경을 그린다.
2. 영웅 그림자와 영웅을 그린다.
3. 영웅 발 y가 물체의 `sort_foot_row_px` 이하일 때 해당 가림 레이어를 위에 그린다.
4. 물체 앞에 선 영웅은 그 물체보다 뒤에 그려지지 않도록 한다.

투명 영역 RGB는 0, 알파는 0/255다. 불투명 픽셀은 배경의 같은 좌표 색과 정확히 일치한다. 배경에 그려진 정적인 물체 그림자는 유지한다. 영웅 발밑 그림자는 목업·미리보기에서 따로 합성했다. 앞쪽 기둥·나무통·깃발을 분리했으며, 먼 상점의 지붕 기둥은 현재 통행 범위보다 뒤에 있어 배경에 남겼다.

## 영웅과 목업

기존 `codex_k070_v1/hero_native_96x128.png`를 그대로 사용했다. 이 자료는 사용자 선택 첫 생성본에서 파생된 73px 영웅이며, 수정본이나 길어진 체형을 기준으로 다시 그리지 않았다. 기준 칸 96×128, 몸 중심 기준 x=48, 발 아래 경계 y=120을 유지했다. 새 캐릭터 시트나 걷기 동작을 만들지 않았으므로 캐릭터 교체·프레임 순서 변경은 없다.

목업의 영웅 발 y는 수리 510, 병영 615, 공방 1008, 상점 870, 계단 735다. 다섯 장소에서 각기 다른 깊이를 보여 주는 동일 영웅의 비교 표본이다. 모든 발의 실제 불투명 하단 경계가 지정한 y에 맞고, 발이 마스크의 흰색 영역에 있음을 확인했다. 원근 배율이 비정수인 곳은 최근접 보간 때문에 원본 점의 반복 너비가 다를 수 있다.

## 확인 결과와 남은 일

에셋 검사에서 3840×1080 크기, 기준 격자 3배 일치, 배경 전체 불투명, 마스크 0/255 및 단일 연결 영역, 가림 레이어 이진 알파·작은 고립 조각 없음·배경 색 일치, 다섯 발 위치, 다섯 장소 범위·접근선, 기준 격자 4배 미리보기를 확인했다. 읽어 사용한 기존 그림·코드 네 파일의 SHA-256도 유지됐다.

브라우저에서 실제 `file://`로 열어 이미지 9개 읽기, 외부 요청 없음, 스크립트 오류 없음, 109.5↔219px 원근 끝점, 가림에 따른 실제 픽셀 변화, 마스크·물체 강조·상호작용 표시, 다섯 장소 버튼, 가로 이동, 100% 표시, 앞뒤 재생, 막힌 곳 클릭 거부, 빈 바닥 배치, 작은 화면 페이지 넘침 없음을 검사했다. 데스크톱·가림 켬/끔·마스크·모바일 화면을 저장하고 확인했다.

`Game/`과 협업 문서는 수정하지 않았다. Unity 실행·실제 게임 캡처·실제 충돌체/카메라/조명 연결 검증은 하지 않았다. 실제 게임 연결과 가져오기 설정, 사용자 Play 확인은 Claude의 후속 작업이다. 새로운 사용자 질문은 없다.

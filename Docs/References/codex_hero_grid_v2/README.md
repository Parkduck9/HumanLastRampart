- hero_walk_run_grid.png: 투명1024×1536, 4열4행, 칸256×384, 공통 발 피벗(128,352). 각 동작4프레임이며 16프레임 보간이 아니다.
- 행은 위부터 0후면 걷기·1왼쪽 걷기·2왼쪽 달리기·3정면 걷기. 기존3행 걷기는 v1 픽셀을 그대로 복사해 보존.
- 오른쪽 걷기: 행1 반전+열2·3·0·1. 오른쪽 달리기: 행2 반전+열0·1·2·3. 모션별 행/위상순서를 섞지 않는다.

## 외형·모션

기존 백발·검정/금색 장교복·갈색 부츠/허리장비·도트 표현을 참조했다. 달리기는 4포즈를 개별 생성하고 C포즈의 금색 견갑 팔이 앞으로 나오도록 수정해 A와 반대 팔 위상을 보이게 했다. 첫4프레임시트2개는 팔교대가 약해 채택하지 않았다. 총7생성호출(미채택2+개별4+팔수정1), 선택4PNG와 프롬프트/출처만 프로젝트에 보관. 달리기 외형·동작은 사용자 검토본이다.

## 정렬과 확인

build_sheet.py는 생성본 전체를 최근접 축척/이동으로 칸에 배치한다. 기존 측면 걷기의 흰 머리 폭을 기준으로 전체 포즈 크기를 정규화한다. 머리 픽셀만 따로 고정/회전하거나 팔다리를 조각내지 않는다. 포즈 전체에3px 상하차를 두고, 공통8px 전방 오프셋으로 뒤쪽 옷자락이 칸에 들어오게 했다. 공중 포즈의 발이 피벗보다 위로 들리는 것은 의도한 모션이다. 각 칸의 월드 기준점은 동일하다.

기존 걷기 픽셀 불변·달리기4칸서로다름·칸잘림없음·발피벗공통·저장픽셀일치 검사 통과. 최초 배치검사에서 B포즈 옷자락이2px 범위를 넘어 실패했고, 포즈 전체 공통오프셋으로 해결해 재검증했다. 원본PNG는 수정하지 않는다.

## M-CL-045 호환 전달본

Claude는 기존3행을 유지하고 달리기를4번째행에 추가해 달라고 요청했다. 그래서 hero_walk_run_append_grid.png/json을 별도로 보관하고 preview.html도 이 호환본으로 연결했다. 행순서는 back0,left1,front2,run3이다. 첫3행은 v1걷기PNG와 바이트일치 확인. 앞서 만든 run2/front3 배치는 보관자료로 남기되 게임에는 append호환본을 권장한다. 기존Game의행번호를 임의로바꾸지않고 Claude에게전달한다.

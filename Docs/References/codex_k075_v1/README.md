# K-075 대포병 동작 시트

2026-10-20. D-080의 **처음 생성한 주인공 6판 generated.png**와 K-065 대포병의 남색·크림색 코트, 갈색 멜빵·장화를 기준으로 제작했다. 크기는 최신 D-081의 인물 약 73점·머리 약 24점 방향을 적용했다. 카드 제목의 크기 미정 표기는 D-081로 대체한다. Game/ 연결은 Claude 담당이다.

검토 페이지: [`codex_K-075_대포병동작_v1.html`](../../../_HTML/4_그림_캐릭터/codex_K-075_대포병동작_v1.html). 이미지 19개와 재생 코드를 모두 내장했으므로 서버 없이 직접 연다. 각 동작의 새 그림·현재 게임 그림을 같은 픽셀 배율과 발선에서 비교한다. 전체 재생/정지, 이전/다음 칸, 처음으로, 속도, 배경, 발선 표시와 원본 펼치기를 제공한다.

## 점화와 견인 좌표

K-043·K-048·K-052의 자료와 실제 게임 파일을 읽었다. 현재 `haul_cannon_body.png`의 도화선은 (269,132), 기준점은 (336,352)이다. 대포를 y=8에 놓으면 새 발선 360과 접점 (269,140)이 된다. 점화 병사의 칸 왼쪽 위를 **(173,0)**에 놓으면 4번째 칸의 불씨 실제 픽셀이 그 접점에 겹친다. 병사의 접촉 픽셀 원본 좌표는 (32,46⅔), 게임 좌표는 (96,140)이다. 정적 합성과 HTML에 같은 좌표를 사용한다. 접촉 0.50초·발사 1.50초는 기존 연결 기준을 설명한 것이며 이번 카드에서 게임 코드를 바꾸지 않았다.

견인은 왼쪽으로 칸당 36게임 픽셀 이동한다. 이는 256 기준 32픽셀을 새 너비 288에 환산한 값이다. 실제 부츠 아래 두 줄의 디딘 발 중심은 원본 **36→48→60 / 36→48→60**이다. 따라서 지면 좌표 `발 x×3 − 칸 번호×36`은 **108/108/108 / 0/0/0**으로 고정된다. 첫 세 칸과 다음 세 칸은 서로 다른 다리의 지지 구간이다. 장화 자체는 통째로 옮기고 바지 영역에서만 위치를 연결했다. HTML의 고정 시점 검사에서는 이동과 칸을 함께 넘기며 매 여섯 칸마다 위치를 초기화한다.

## 제작과 프롬프트 묶음

내장 image_gen 9회로 원안을 만들었다. 외부 API·CLI 생성·Python 이미지 편집은 사용하지 않았다. `generation.json`은 원안과 채택 여부, `source/`는 생성 원안 9장이다. 원안의 부드러운 외곽과 광택은 최종 시트에서 알파 임계값 128, 작은 고립 성분 제거, 최근접 축소, 23색 제한으로 정리했다. 새 최종 PNG는 알파 0/255만 사용한다.

프롬프트의 한국어 요약은 다음과 같다. 공통으로 K-065 대포병 정체성, 선택한 첫 주인공 6판의 큰 머리·파란 홍채와 흰 반사점·굵은 어두운 윤곽·짧은 몸·큰 장화·재질별 약 세 단계 명암, 투명 배경·가로 한 줄·동일 배율·글자와 지면 없음 조건을 사용했다.

1. 대기: 뒷모습 한 명, 교차 멜빵과 오른손의 꺼진 점화 막대, 같은 높이의 두 발.
2. 달리기: 왼쪽을 향하는 네 칸. 첫 초안의 반복되는 다리를 수정해 넓은 디딤과 좁은 통과 자세가 번갈아 나오도록 요청했다.
3. 점화: 여섯 칸의 막대 내림·들기·접근·접촉·거두기·복귀, 발 고정. 너무 높은 첫 막대를 줄이고 접촉 불씨를 머리 꼭대기 근처로 낮추는 수정 요청을 적용했다.
4. 쓰러짐: 기존 게임 그림을 직접 참조해 뒷모습과 엎드리는 마지막 칸을 유지하는 네 칸. 정면 초안은 채택하지 않았다.
5. 밀기: 왼쪽으로 기울고 두 손을 왼쪽으로 뻗는 여섯 칸, 두 다리의 지지 구간과 들린 반대 발, 막대 없음.
6. 당기기: 왼쪽으로 기울되 두 손은 뒤인 오른쪽으로 뻗는 여섯 칸, 같은 보행 구간, 막대와 대포·밧줄 없음.

재현은 저장소 루트의 PowerShell에서 이 폴더 `build.ps1` → `verify.ps1` → `build_review.ps1` 순서다. 보관한 원안만 사용하므로 추가 생성이 필요 없다. 이후 Node에서 `verify_review.cjs`의 `verify(저장소절대경로)`를 호출한다. 원안 후보 파일은 최종 교체 대상이 아니다.

## 확인과 남은 검토

- PNG 실제 픽셀 검사 **154항목 통과**: 6종 크기·27칸 발선·가장자리 여백·3픽셀 미만 고립 성분 없음·이진 알파·프레임 구분·점화 하체 일치·견인 접지·점화 높이·3배/4배 픽셀 일치·Game 원본 해시 유지. `validation.json`에 결과를 보관했다.
- HTML 실제 스크립트를 Node VM의 DOM·Canvas 모형에서 실행해 **38항목 통과**, 192회 그리기 범위 확인. 내장 이미지 19개, 원본 파일 일치, 재생·정지·앞뒤·순환·초기화·속도·배경·발선·접점 검사를 포함한다. `review_validation.json`에 기록했다.
- 최종 6종 확대 시트와 점화 합성을 직접 열어 확인했다.
- 연결된 브라우저 목록이 비었고 실제 페이지 열기는 `Browser is not available: iab`로 실패했다. **실제 브라우저의 화면 배치·이미지 디코더·마우스 조작·실시간 재생 육안 확인은 미수행**이다. Node 모형 검사를 실제 브라우저 검사로 기록하지 않았다.
- Unity·Play·게임 캡처·Git 쓰기·Game/·live 기록·기존 HTML·전체 목록 수정은 하지 않았다. Docs의 검토 자료이므로 `.meta`는 만들지 않았다. 연결 시 기존 Game 에셋 GUID를 보존하고 칸·피벗·관련 노멀맵을 Claude가 맞춰야 한다.
- 외형상 남은 검토: 파란 눈의 가독성과 재질별 명암, 달리기와 견인 6→1 연결, 견인 바지 보정·다리 구분·손과 포가의 파지, 점화 중 포미·바퀴와 인물이 겹치는 정도. 현재 대포와 도화선의 실제 픽셀 좌표는 맞췄으나 장면 전체의 배치 채택은 사용자 검토가 남는다.
- 게임의 연속 이동 중 접지는 이 시트의 칸당 이동량과 별도로 연결 검증이 필요하다. 기존 크기의 노멀맵을 그대로 사용하면 맞지 않는다. 새 노멀맵은 이번 카드 범위에 포함하지 않았다.

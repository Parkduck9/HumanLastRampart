- 작업: T-CX-058 / M-CL-075·076 / 가지 card/K-017.
- 상태: **시안·사용자 확정 전. Game 연결 없음.**
- 제작: built-in imagegen. 원본 이미지7장(최초5종·달리기와오르기 보완2장), 정확한 프롬프트·참조·원본경로·해시를 generation.json과 sources/에 보관했다.
- 기존 정적/걷기 사다리 고블린을 직접 확인했다. 녹색피부·검은모히칸·노란눈·엄니·갈색옷/목도리/장화·2.2등신을 유지하는 방향이다. 원본 Art/캐릭터 데이터는 수정하지 않았다.

## 크기와 앵커 규격 제안

- 성벽 높이4m·병사키0.35m는 현재 기록 기준이다. 사다리 실체길이 **4.3m는 제안**이다. 실제 난간/갈고리 걸침높이와 발끝 거리는 3D 연결 뒤 확인한다.
- 사다리 실체는1152px, 하단 기준(128,1472), 상단 갈고리 중심의 참고점(128,320)이다. 정면은 두 갈고리 사이의 중심을 가리킨다. 정확한 개별 갈고리 접점은 별도 확인이 필요하다.
- 사다리 PNG 전체높이는1536px이다. 전체 칸을4.3m로 설정하면 실체가 짧아지므로 **실체1152px = 4.3m**로 계산한다. 제안 PPU=1152/4.3≈267.91, 전체 칸높이≈5.733m. Unity 왼쪽아래 피벗은(0.5,0.0416667)이다.
- 인물은 기존 칸/발 규칙을 유지한다. Unity 피벗(0.5,0.0833333). 전투키0.35m를 맞출 때는 각 시트의 실체최대높이(manifest.maxBodyHeight)를 기준으로 하고 투명칸 전체를0.35m로 잡지 않는다. 이 값은 연결 API 확정이 아닌 계산 참고다.
- 문자·치수를 그림에 그려 넣지 않았다. 사다리색/캐릭터색/알파를 코드로 덧칠하거나 노멀맵을 만들지 않았다.

## 기술 작업

생성 원안을 보존하고 alpha>16 실체 경계를 측정해 자르기, 비율을 유지한 최근접 축소, 투명 격자 배치만 수행했다. 각 인물 시트 안의4프레임은 하나의 공통 축소율을 쓴다. manifest.json에 원본 사각형·완성 실체사각형·기준점·해시를 기록했다. 매우 낮은 알파의 바깥 halo는 실체 경계 자르기에서 제외될 수 있으며, 내부 낮은 알파·색은 바꾸지 않았다.

## 동작 및 모양 검토

직접 원안7장과 최종12칸을 확인했다. 처음 달리기1·3번의 같은 다리 반복을 발견해3·4번 다리를 보완 생성했고, 현재 앞발이 좌→우로 바뀐다. 오르기 팔은1·2번 왼팔 /3·4번 오른팔 위주로 보완했다. 후면2번의 위쪽 손이 머리뒤에 일부 가려지는 점은 사용자 검토 대상이다.

정면·측면 소품은 각각 생성한 시안으로 가로대 개수/간격이 완전히 같은 정밀3D도면이 아니다. 손과 가로대의 정밀 접점, 세우기 중 힘의 전달, 최종 난간 가림·갈고리 걸침,4m벽/0.35m인물 사이의 실제 가독성은 게임 연결 전후 검토가 필요하다. 시트를 게임사용완료·최종승인으로 표시하지 않는다. 노멀맵도 이번 범위에 없다.

## 확인 HTML과 재생

_HTML/codex_K017_사다리_v1.html 및 preview.html은 이미지/JS를 내장한 같은 단독파일이다. 서버 없이 직접 열 수 있다.

- 3동작 선택, 재생/정지, 이전/다음프레임, 프레임슬라이더,4/6/8FPS,1/2배 확대,체커/어두움/밝음 배경,정면/측면 소품 선택.
- 확대 뷰는 인물만 보여 주고 별도 합성 뷰는4m벽/0.35m병사 비율을 유지한다.2배 선택 시 미리보기를 한열로 넓히고 좁은창에서는 가로스크롤을 쓴다.
- 세우기 소품은 아래에서 올라와 기울어지는 위치 목업이며, 오르기 높이도 목업이 제공한다. 새 아트를 코드로 만드는 기능이 아니다. 실제 게임 캡처나 사다리 물리 시험으로 보지 않는다.

재생성: build.py → node test_playback.cjs → verify.py. Python Pillow/NumPy 및 Node가 필요하다. 브라우저 수정결과는 별도 QA 기록을 확인한다.

## 검증

정적 자료/해시/격자/투명도/내장PNG 검사51/51, Node 재생상태 단위검사18/18, JS 구문 검사 통과. 이 숫자는 Unity 시험 건수가 아니다. 실제 브라우저 확인은 부모 작업자가 수행해 공유한 결과를 qa.json의 별도 browserReview에 기록한다. 이 카드 작업자의 CUA에는 사용 가능한 브라우저가 없었다. 부모가 발견한 정지 중 상태문구 오표기와2배뷰 잘림을 수정했다.

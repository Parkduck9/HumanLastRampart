# K-087 토벽·언덕 이음 부품

토벽의 직선·대각 부품, 양끝 마감, 접합 기둥과 지도용 토벽·언덕 중심/8방향 팔을 제작했다. Game/ 원본은 수정하지 않았다. 게임 연결은 Claude가 담당한다.

검토 페이지: [_HTML/5_그림_전장/codex_K-087_토벽언덕이음_v1.html](../../../_HTML/5_그림_전장/codex_K-087_토벽언덕이음_v1.html). 이미지를 내장했으므로 파일을 직접 열 수 있다. 이웃 방향 선택, 지형 선택, 손상 4상태 자동 전환·정지를 제공한다. 기존 게임 그림과 새 부품을 나란히 비교한다.

## 전투 부품

높이 방향과 길이 방향 모두 기본 40픽셀/m이다. 온전함·균열은 풀을 포함한 최대 높이 112픽셀 = 2.8m다. 붕괴·잔해의 등록 범위는 각각 72픽셀·36픽셀이며, 실제 불투명 실루엣은 부품마다 다르다. 직선 부품의 실측은 붕괴 59픽셀 = 1.475m, 잔해 35픽셀 = 0.875m다. 부품별 실제 높이는 manifest의 `visible_height_px`/`visible_height_m`에 기록했다. 손상 상태마다 별도 원화 행을 사용했다. 캔버스 높이와 바닥 피벗은 모든 상태에서 같다.

| 부품 | 원본 캔버스 | 게임용 3배 | 길이/역할 |
|---|---|---|---|
| 직선 | 200×128 | 600×384 | 5m, 양 끝 같은 색·알파 |
| 대각 | 283×128 | 849×384 | 5√2m ≈ 7.071m |
| 왼쪽 끝 | 32×128 | 96×384 | 노출된 시작점 마감 |
| 오른쪽 끝 | 32×128 | 96×384 | 노출된 끝점 마감 |
| 접합 기둥 | 48×128 | 144×384 | 이음·코너를 덮는 폭 1.2m |

원본은 `native/`, 게임용은 `game/`에 있다. 게임용은 원본의 최근접 보간 3배이며 120픽셀/m이다. 지형 전용 규격이므로 인물용 96×128/288×384 셀과 다르다.

피벗은 아래 중앙 `(0.5, 0)`, 바닥선은 위에서 잰 픽셀 **경계** y=128(게임용 y=384)이다. 마지막 불투명 픽셀 행은 y=127(게임용 y=383)이다. 바닥 기준을 그림의 알파 바운딩 박스로 다시 계산하지 않는다. 대각 길이는 래스터 반올림으로 283픽셀을 사용한다. 40픽셀/m로 읽으면 7.075m이며 목표 길이와 약 3.9mm 차이다. 배치 좌표의 두 셀 중심 간 거리는 정확히 5√2m를 사용한다.

각 상태의 `*_sheet.png`는 **직선 / 대각 / 왼쪽 끝 / 오른쪽 끝 / 접합 기둥** 순서다. 원본 셀은 288×128, 게임용은 864×384다. 부품 자체의 폭은 위 표와 같고 나머지는 투명 여백이다. 홀수 폭 대각의 0.5픽셀 중심 차이를 보정할 수 있도록 manifest에 각 부품 사각형과 피벗도 기록했다. 정확한 길이로 그릴 때에는 개별 부품을 쓰거나 이 사각형으로 잘라 사용한다.

기존 이름 `earthwall_intact.png`, `earthwall_cracked.png`, `earthwall_collapsed.png`, `earthwall_rubble.png`도 원본/게임용 폴더에 각각 보존했다. 모두 기존과 같은 1프레임이며 해당 상태의 새 직선 부품과 같다. 새 5프레임 부품 시트는 별도 이름이다. 기존 Game/ 파일은 교체하지 않았다.

전투에서는 길이 축을 이웃 방향의 XZ 평면에 놓고 높이 축을 세운다. 스프라이트를 화면 평면에서 회전하여 기울이면 높이와 바닥이 어긋난다. 뒤쪽 선분부터 그린 뒤 노출 끝에는 마감, 연결점에는 접합 기둥을 덮는다. 코너와 손상 상태가 바뀌는 이음에서도 기둥이 마지막에 온다. 상태가 다른 벽의 높이 차이는 실제 손상 표현으로 남는다.

## 지도 부품

`map/`은 확대하지 않은 32×32 PNG다. 한 셀은 5m이므로 6.4픽셀/m이다. 토벽·언덕 각각 중심 1개와 팔 8개를 제공한다. 시트는 **중심 / 북 / 북동 / 동 / 남동 / 남 / 남서 / 서 / 북서** 순서로 총 9프레임, 288×32다.

중심·팔의 피벗은 위에서 잰 `(16,16)`이다. 팔의 시작은 `(16,16)`, 끝은 방향에 따라 `(16,0)`, `(32,0)`, `(32,16)`, `(32,32)`, `(16,32)`, `(0,32)`, `(0,16)`, `(0,0)`이다. 좌표는 픽셀 중심이 아닌 **경계 좌표**다. 32는 이웃 셀과 공유하는 경계이며 잘못된 33번째 픽셀을 뜻하지 않는다.

비트 순서는 북=1, 북동=2, 동=4, 남동=8, 남=16, 남서=32, 서=64, 북서=128이다. 모든 중심을 먼저 놓고 연결된 팔들을 그 위에 겹친다. 이웃에는 반드시 반대 팔도 켠다. 대각 팔은 셀 모서리를 두껍게 채워 단순한 점 접촉보다 넓게 닫힌다. 방향이 여러 개 모이는 중심에서는 같은 중심 원화 픽셀을 공유해 짙은 선이 한가운데를 가르지 않도록 했다.

한 번의 배치가 차지하는 셀은 정확히 두 개다. 그림의 팔은 자동 이음 표시이며 차지하는 셀 수를 늘리지 않는다. 대각 모서리의 이동 차단, 이웃 마스크 계산, 두 셀 배치 제한은 게임 코드에서 적용해야 한다.

## 예시와 원화

`previews/layout_examples.png`는 직선 조각 3개, 직각, 대각, 대각+직선, 언덕 능선을 전투/지도 시점으로 배치한 투명 시트다. 개별 예시 PNG와 부품 시트 4배 미리보기도 같은 폴더에 있다. 예시마다 manifest의 `placement_pairs`에 실제 두 셀 묶음을 기록했다. 토벽 전투 예시는 부품을 길이 방향으로 투영하여 조립한 검토 그림이다. 언덕 전투 예시는 **새 지도 부품을 지면에 투영한 모습**이며 새 전투 언덕 입체 그림은 이 카드의 제작 대상에 포함하지 않았다. Unity 캡처가 아니다.

`source/`에는 내장 image_gen으로 생성한 원화와 배경 분리본을 보관했다. 첫 토벽 생성본의 배경은 채택하지 않았고 분리본의 알파를 사용했다. 이후 작업은 잘라내기, 알파의 0/255 정리, 떨어진 픽셀 제거, 기준선 정렬, 원화 픽셀 복사로 반복 경계 맞추기, 최근접 보간, 팔 방향 변환과 시트 조립이다. 생성 경로·프롬프트는 `source/generation.json`에 있다. 제작·검증 스크립트의 외부 패키지는 Pillow와 NumPy이며 브라우저 검증은 기존 Playwright를 썼다.

## 검증 범위

`verification.json`은 크기·RGBA·이진 알파·투명 영역 RGB·부품 연결 성분·바닥 접촉·반복 경계·3배 확대 일치·양방향 팔과 대각 모서리·두 지형의 256가지 마스크·예시의 두 셀 묶음을 검사한다. `review_validation.json`은 서버 없이 HTML을 열어 이미지 로드, 자동 전환·정지, 방향 선택, 모바일 넘침과 브라우저 오류를 검사한다. 브라우저 캡처는 `review/`에 있다.

Unity 실행, 실제 게임 적용, 카메라에서의 크기와 정렬, 이동 차단 검증은 수행하지 않았다. 외형 검토 후 Claude 연결과 사용자 Play 확인이 남아 있다.

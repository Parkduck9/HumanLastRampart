## 크기와 기준점

초상은 기존 K-028과 같은 파일명·512×512 캔버스입니다. 가로 중심 256, 흉상 하단 480, 인물 높이 약 440을 유지했습니다. 초상에는 발 기준선을 적용하지 않습니다.

작업자는 게임의 현재 `TrapMap/worker_*.png`와 같은 파일명·캔버스·칸 수를 유지했습니다. 한 칸 256×384, 가로 네 칸, 발 기준선은 위에서 352입니다. 논리 격자 64×96에서 정리하고 4배 확대했습니다. 작업자의 기존 칸별 점유 높이와 몸통의 가로 위치를 기준으로 삼아, 도구를 포함한 비대칭 배치를 유지했습니다. 일반 전투 인물의 새 크기 결정은 적용하지 않았습니다.

셀 기준점은 (128,352)이며 기존 텍스처를 교체할 때 Unity의 가져오기 설정은 그대로 유지해야 합니다. 실제 그림의 몸통 위치는 도구 배치 때문에 셀 중앙과 다를 수 있습니다. 칸별 배치·수평 기준은 매니페스트에 기록했습니다. 원본 픽셀 범위를 논리 격자에 맞추면서 최대 몇 픽셀의 반올림 차이가 있습니다.

땅 파기는 왼쪽부터 **삽 세우기 → 삽 누르기 → 흙 들어 올리기 → 흙 던지기**입니다. 흙·통나무 나르기는 기존 순서의 네 보행 자세입니다. 땅 파기의 큰 흙 조각은 동작 요소로 남겼고 두 논리 픽셀 이하의 분리된 조각은 제거했습니다.

## 제작과 확인

내장 `image_gen` 도구로 인물별 11회 생성했습니다. 모든 호출은 첫 생성본을 스타일 기준, 교체할 기존 에셋을 구도·동작 기준으로 사용했습니다. 프롬프트 전문은 `source/prompts.json`에 있습니다. 생성 후 알파 224 미만을 투명하게 정리하고 최근접 보간으로 격자를 맞췄습니다. 공통 33색 팔레트와 한 논리 픽셀 외곽선을 적용했습니다. 재질별로 약 세 단계 명암을 목표로 했으며 전체 색상 수가 세 색이라는 의미는 아닙니다.

납품 PNG 11종 모두 원본과 크기가 같고, 투명·불투명 픽셀이 있으며 중간 알파는 없습니다. 프레임마다 작업자 하단 352·초상 하단 480, 최근접 보간 격자, 두 논리 픽셀 이하의 고립 조각 없음, 4배 확대본 크기를 검사했습니다. 기존 UI·K-028 원본 199개의 SHA-256도 동일했습니다. 출력 11종은 직접 열어 확인했습니다.

검토 페이지의 내장 PNG 34개를 해독했고 17개 캔버스의 로딩, 재생 진행, 칸 선택, 재생 재개, 배경 전환은 모의 DOM에서 확인했습니다. **연결된 브라우저가 없고 내장 브라우저도 사용할 수 없어 실제 브라우저 표시·레이아웃·동작 재생은 미검증입니다.** 이 검사는 실제 화면 캡처를 대신하지 않습니다.

## 연결과 남은 것

기존 K-028 배경·장소·결과 합성 그림과 `Game/`은 수정하지 않았습니다. K-033 참조 폴더는 현재 작업 폴더에 없었으므로 작업자는 실제 게임 PNG를 기준으로 삼았습니다.

현재 `ResultBoard.cs`는 별도 결과 초상 PNG 대신 병종 정의의 서기 시트 또는 기본 시트 첫 칸을 사용합니다. 검토 페이지 가운데에 그 시트를 표시했고, 정의 파일의 GUID와 실제 시트 경로를 대조했습니다. 새 결과 초상을 게임에서 보이게 하는 연결은 Claude의 후속 작업입니다. 작업자 PNG는 기존 이름으로 교체할 수 있지만 이 카드에서는 게임에 복사하지 않았습니다.

사용자가 비교 페이지의 인물 비율·작업 동작을 검토한 뒤, Claude가 에셋 교체·결과 초상 연결을 진행하고 사용자가 Unity Play에서 최종 확인해야 합니다. Unity 실행·실제 게임 캡처·Git 쓰기는 수행하지 않았습니다.

재출력은 `source/export.ps1`, 에셋 검사는 `source/verify.ps1`입니다. 저장된 `originals/`를 우선 사용하므로 외부 생성 폴더 없이 재출력할 수 있습니다. HTML 생성은 `source/build_review.mjs`의 `build(저장소루트)`, 모의 검사는 `source/verify_review.mjs`의 `verify(저장소루트)`를 Node.js 환경에서 호출합니다.

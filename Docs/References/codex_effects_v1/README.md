## 제작 방식

built-in imagegen으로 각 효과의 여섯 동작을 하나의 투명 원안에 생성했다. 기존 주인공의 도트 굵기를 먼저 확인했다. 첫 원안은 빛 번짐이 강해 채택하지 않았고, 불투명 제한색과 어두운 도트 외곽선을 명시해 새로 생성한 원안을 채택했다. 실제 원안·정확한 프롬프트는 `_source.png`와 jobs.json, 규격·크롭·해시는 각 JSON/manifest.json에 보관한다.

원안의 프레임 사이 투명 공백을 찾아 여섯 구역으로 나누고 동일 시트 안에서는 **같은 배율과 같은 세로 범위**를 사용해 최근접 정렬한다. 폭발이 커졌다가 작아지는 동작을 각 칸마다 확대해 없애지 않는다. 효과 종류 사이의 크기 차이는 의도적이다. 화살·총알 명중은 작게, 마법·함정은 크게, 횃불은 좁고 세로로 보이도록 한다. 내용 덧칠·프레임 복제·후처리 발광은 하지 않는다. 아래 경계는 지면/발화 지점 피벗이라 의도적으로 접한다.

## HTML 확인

`_HTML/codex_K012_효과도트_v1.html` 또는 이 폴더 preview.html을 서버 없이 직접 연다. PNG와 문서를 내장했다. 효과 선택, 재생/정지, 이전/다음 칸, 원샷 한 번 재생, 8/10/12fps, 1배/2배, 밝은/어두운 배경을 비교할 수 있다. 수동 칸 이동은 정지하고, 재생 버튼으로 자동 진행을 다시 시작한다.

build.py는 원안에서 PNG·메타·HTML·qa.json을 재생성한다. Pillow·NumPy와 Node가 필요하다. verify_player.cjs는 DOM 모형에서 자동 재생·정지·수동칸·원샷·효과 전환 등을 확인한다. 실제 브라우저 렌더링 검증과 동일한 검사는 아니다.

## 한계와 남은 확인

AI 그림의 미세한 도트·조각 분포와 두 루프의 6→1 연결은 사용자 외형 검토가 필요하다. 원안 가장자리에는 미세한 반투명 픽셀이 남을 수 있어 밝은 배경에서도 확인한다. 투명 알파가 존재한다는 검사만으로 게임 안에서 모든 배경 흔적이 없다고 확정하지 않는다.

노멀맵·실시간 발광·횃불 빛·폭발 광원·피해/범위·연기 입체화는 포함하지 않는다. Claude K-010의 빛과 짝지을 시 색/세기/타이밍·실제 전투 크기를 따로 검토한다. Unity 실행·게임 연결·실제 프레임률/성능 검증은 하지 않았다. 최종 도입은 사용자 외형 검토와 Claude 연결 후 실제 캡처 비교 단계가 남아 있다.

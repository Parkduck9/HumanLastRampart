# K-097 튜토리얼 보충 그림

W2 안내 순서인 걷기 → 망원경 → 지도 → 분대 → 대포 설명 → 마법 → 함정 → 망원경 업그레이드에 맞춘 화면 부품이다. 그림만 제작했으며 게임 파일은 수정하지 않았다.

## 납품 구성

| 이름 | 원본 칸 | 칸 수 | 내용 |
|---|---:|---:|---|
| `instruction_box_9slice` | 96×48 | 1 | 명령서 판, 장식이 늘어나지 않도록 중앙 정리 |
| `hint_chip_9slice` | 48×24 | 1 | 어두운 바탕의 빈 힌트 판 |
| `officer_expressions` | 48×48 | 4 | 기본 / 설명·손들기 / 긴급 / 만족 |
| `highlight_ring_pulse` | 64×64 | 6 | K-093 강조 고리 재사용, 초당 8칸 |
| `pointer_bounce_up/right/down/left` | 32×32 | 각 4 | 네 방향, 초당 6칸 |
| `step_icons_24` | 24×24 | 8 | 안내 순서별 작은 아이콘 |
| `step_pips` | 32×32 | 24 | 단계별 대기 / 현재 / 완료 |
| `step_progress_strip` | 256×32 | 9 | 8단계가 나란히 있는 완성 띠, 진행 상태 9종 |
| `input_chips_24/32` | 24×24 / 32×32 | 각 5 | Shift+끌기 / 우클릭 / 휠 / E / Esc |

13종, 총 79칸. 모든 시트는 가로 한 줄이다. `이름_native.png`는 원본, `이름.png`는 정확한 최근접 3배 게임용, `이름_4x.png`는 원본의 최근접 4배 검토용이다. 게임에 이미 연결된 파일을 교체하지 않는다.

## 연결 규격

- 두 9-slice 판의 Unity Sprite Editor Border는 **게임용 왼쪽 24 / 아래 24 / 오른쪽 24 / 위 24px**, 원본은 모두 **8px**이다. Image Type은 Sliced, 중앙과 가장자리는 늘리기 방식이다. 게임용 최소 크기는 51×51px이다. 고정 테두리가 겹치는 크기로 줄이지 않는다.
- 글자는 판에 포함하지 않았다. 글 안전 여백은 원본 기준 왼쪽·오른쪽 10px, 위·아래 9px이다. 힌트 판은 짧은 한 줄 입력 안내용이다.
- 모든 칸은 중앙 피벗 `(0.5, 0.5)`. 흉상은 K-093과 같은 48×48, 원본 피벗 `(24,24)`, 게임용 `(72,72)`이다. 흉상 밑선은 원본 y=46 직전까지 채웠다. 설명 표정은 머리를 기준으로 정렬해 손 때문에 얼굴이 옆으로 밀리지 않게 했다.
- 전신 캐릭터가 아닌 UI·흉상이므로 D-081의 96×128 전신 칸과 발 y=120은 적용하지 않는다. 고리는 원본 `(32,32)`, 포인터는 `(16,16)` 중심에서 동작한다. 포인터의 이동은 의도한 튀기기 동작이다.
- `step_pips` 인덱스는 **단계 번호(0부터) × 3 + 상태 번호**. 상태 번호는 대기 0 / 현재 1 / 완료 2다. 각 32px 칸에 24px 아이콘이 들어간다. 현재는 금색, 완료는 초록 테두리와 확인 표시, 대기는 회색이다.
- `step_progress_strip` 0~7칸은 해당 단계 진행 중, 8칸은 전부 완료다. 각 칸 안에는 8단계가 모두 들어 있다. 띠 자체의 재생 속도는 정하지 않았다. 실제 단계 변경 때 해당 칸을 선택한다.
- 입력 칩의 우클릭·휠·E는 K-093의 동일한 크기 원본에서 그대로 추출했다. 키보드의 E / Esc / Shift 표기는 실제 키 표기를 따른다. 조작 설명은 게임에서 한국어 글자로 함께 표시한다.
- 필터 Point, 압축 없음, Mipmap 끔을 권장한다. 구체적인 크기·피벗·순서·출처 해시는 `manifest.json`에 있다. Sprite Editor 설정과 게임 연결은 Claude 담당이다.

## 제작 근거와 재사용

장교는 사용자가 선택한 주인공 v6의 **generated.png**를 인물 기준으로, K-093 흉상을 화면 구성 기준으로 사용했다. 내장 imagegen으로 4표정 원본을 생성하고, 같은 축척으로 최근접 축소·머리 중심 정렬·알파 이진화·색 양자화·고립 영역 정리를 거쳤다. 흰 머리, 파란 눈과 흰 반사점, 검정 장교복, 금색 견장과 테두리를 유지했다. 생성 원본 `officer_expressions_generated.png`는 제작 자료이며 게임에 직접 넣는 파일이 아니다. 생성 지시문은 `generation_prompt.json`에 보관했다.

K-093의 명령서·고리·네 방향 포인터·입력 칩·잠금 부품·완료 도장과 6장 합성 목업을 확인했다. 이번에는 부족한 힌트 판·표정·4칸 포인터·8단계 진행·Shift+끌기·Esc를 보충했다. 기존 고리와 일부 입력 칩은 모양을 바꿀 필요가 없어 재사용했다. K-093 폴더는 변경하지 않았다.

## 검토와 검증

검토 페이지: `_HTML/6_그림_화면/codex_K-097_튜토리얼보충_v1.html`. 그림과 스크립트가 모두 내장되어 서버 없이 직접 연다. 표정 비교, 고리·포인터 자동 재생과 일시정지·한 칸 넘기기, 안내 판 너비 조절, 단계 선택을 제공한다. 기존 K-093 시트와 현재 게임 장교 동작을 나란히 표시한다. 현재 게임 아트 경로에는 튜토리얼 전용 시트가 없어 K-093 자료를 게임 적용 전 비교 기준으로 표시했다.

검사한 항목:

- 13종·79칸 크기, 모든 납품 시트의 0/255 알파, 3배·4배 모든 픽셀 일치.
- 프레임별 알파 경계와 연결 영역. 가장 작은 독립 영역은 65점이며 의도하지 않은 작은 고립점은 없다. 흉상 4칸의 밑선과 칸 안쪽 여백 확인.
- 두 9-slice 판의 중앙 균일성, 테두리 값, 확대용 원본 크기 확인.
- 내장 PNG 19개 디코드, 그리기 원본 영역의 시트 경계 준수, 스크립트 자동 재생·정지·한 칸 넘기기 유지, 단계 9상태, 너비 180/900px 동작 검사. `verify_review.cjs`의 Node 가상 DOM 검사이며 실제 브라우저 검증은 아니다.

실제 브라우저는 실행 연결을 확보하지 못했다. headless Chrome 디버깅 연결이 열리지 않았고 컴퓨터 사용 도구의 브라우저 목록은 비어 있으며 내장 브라우저도 사용할 수 없었다. 따라서 실제 HTML 배치·브라우저 재생·작은 화면 배치 확인은 남아 있다. Unity는 실행하지 않았으며 Sprite Editor 설정, 실제 게임 크기·문구 배치와 수행 판정도 확인하지 않았다.

재생성은 Windows PowerShell에서 `build.ps1` → `finalize.ps1`, 페이지 스크립트 검사는 Node에서 `verify_review.cjs`를 실행한다. `build.ps1`은 K-093의 그림 함수 정의만 읽으며 그 카드의 제작 실행부는 실행하지 않는다. 결과는 이번 폴더와 지정 검토 HTML에만 쓴다.

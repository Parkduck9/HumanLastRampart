검토 페이지: `_HTML/4_그림_캐릭터/codex_K-070_인물크기비교_v1.html`.
이미지·스타일·스크립트 내장형이며 서버 없이 직접 연다.

추천은 **인간73px · 96×128칸**이다. 선택 영웅의 고유 격자 추정 키73px와 눈·머리의 점 밀도를 이어가기 좋다. 화면 키70~90px에서는52px의 비정수 확대보다 형태를 더 많이 유지한다. 프레임 수는 그대로지만64×96 대비 칸당 RGBA32 메모리는24→48KiB로2배다. 최종 선택과 게임 연결은 이번 카드에서 확정하지 않는다.

원안은 알파128 이진화 → 종횡비를 유지한 최근접 축소 → 중심/발선 배치 → 기존 K-065/K-066 최종 그림의 실제 색 집합에 대응했다. 부위별로 머리나 팔다리를 따로 늘이지 않았다. 생성 원안은 완전한 균일 격자가 아니며 정규화 과정에서 한 점 정도의 국소 차이가 생길 수 있다. 앞뒤 정지 그림은 완성된 동작 시트가 아니다.

## 비용과 검증

64×96→96×128은 칸 면적 정확히2배다. 같은6프레임이면384×96·144KiB→576×128·288KiB, 6×4프레임이면384×384·576KiB→576×512·1,152KiB다. RGBA32·밉맵 없음·압축과 아틀라스 여백 없음 기준이다. 프레임 수나 재생 시간은 키만으로 바뀌지 않는다. 밉맵은 대략4/3배, 같은 크기 노멀맵은 별도 추가다. 기존 게임256×384칸 계약·피벗·가져오기 변경은 후속 작업이다.

- `build.py`: 원안부터 최종PNG·내장HTML·정적 검사를 재생성한다. Pillow와 NumPy가 필요하다.
- `validation.json`: 키·칸·발선·이진알파·팔레트·정수4배·세 비교대상 동일 화면 키73px·내장PNG 디코딩·원본 해시 검사 결과.
- `source_hashes_before.json`: Game 전체와 기존 K-065/K-066·영웅 원본·K-068 입력, 총1,231개 파일의 시작 해시. 최종 재검사에서 모두 유지됐다.
- `verify_review.cjs`, `review_validation.json`: 실제 Chrome에서 로컬HTML 열기, 내장 이미지 디코딩, 1배480px/4배1920px 비교판3개, 목업800px 유지, 스크립트 오류0, 모바일390px에서 페이지 가로 넘침 없음 확인. 개발 환경의 Playwright·Chrome이 필요하다.
- `review_desktop_1x.png`, `review_desktop_4x.png`, `review_mock.png`, `review_mobile.png`: 위 브라우저 확인 캡처.

Unity 실행·Play·새 게임 캡처·동작 제작·Game 연결·Git 쓰기는 수행하지 않았다. 지정 출력 폴더, 지정 HTML, 루트 CARD_RESULT.md만 작성했다. 사용자 결정이 남아 있다.

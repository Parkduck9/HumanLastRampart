# K-092 반사 강도·매끄러움 마스크

현재 게임 폴더의 원본 **41개 시트, 142프레임**에 대응하는 RGBA 마스크입니다. 캐릭터 폴더의 사다리 소품·투사체와 대포 폴더의 운반병·포신·바퀴·연기도 포함했습니다. 기존 `_normal.png`는 대상 원본 시트 수에서 제외했습니다.

검토 페이지: [반사 마스크 검토](../../../_HTML/5_그림_전장/codex_K-092_반사마스크_v1.html). 브라우저에서 파일을 직접 열면 됩니다. 이미지와 스크립트가 내장되어 서버나 인터넷 연결이 필요하지 않습니다.

## 채널과 재질

R은 반사 강도, G는 매끄러움, B는 항상 0입니다. A는 원본 알파의 바이트를 그대로 복사했습니다. 값은 0~255 정수로 저장하며 셰이더에서 255로 나눠 사용합니다.

| 재질 | R | G | 적용 위치 |
|---|---:|---:|---|
| 무광 | 13 (0.051) | 26 (0.102) | 천, 피부, 머리, 흙, 나무, 뼈, 눈·옷깃의 밝은 부분 |
| 가죽 | 77 (0.302) | 64 (0.251) | 갈색 장화, 장갑, 가죽 허리띠·끈 |
| 거친 철 | 242 (0.949) | 140 (0.549) | 대포의 철제 포신과 테, 오우거 버클, 사다리 금속 고리, 화살촉, 포탄 |
| 매끈한 금속 | 255 (1.000) | 191 (0.749) | 총열, 대포의 밝은 금속 면·고리 |
| 금색 장식 | 255 (1.000) | 217 (0.851) | 주인공 견장·테두리, 마법사 목·옷 장식, 고블린 버클, 대포병의 작은 금속 장식 |
| 발광 효과 | 0 | 0 | `bullet_trace`, `muzzle_smoke` 전체 |

현재 원본 대포는 회색 철과 갈색 나무로 표현되어 있어 그 구분을 따랐습니다. 청동색을 새로 그리지 않았습니다. 총의 나무 개머리판과 고블린 몽둥이는 낮은 반사값을 유지합니다. 검은 외곽선은 무광으로 두었습니다. 피부와 비슷한 밝은 견장·옷깃도 천으로 취급했습니다. 마법사의 보석·눈에는 금속 반사를 추가하지 않았습니다.

재질은 원본 색과 프레임 안 위치로 나누고, 총열은 프레임별 선분 영역으로 따로 지정했습니다. 정수 확대 원본은 작은 도트 격자에서 분류한 뒤 최근접으로 확대하여 3×3 도트 중간에 재질 경계가 생기지 않게 했습니다. 흐림이나 보간을 사용하지 않았습니다. 재질 분류는 자동 규칙과 위치 지정에 기반하며, 검토 페이지에서 동작별로 확인할 수 있습니다.

## 파일 구성

- `Characters/<원본 하위 폴더>/<원본 이름>_spec.png`: 게임 원본과 정확히 같은 크기·프레임 배치의 마스크 34개.
- `Cannon/<원본 이름>_spec.png`: 대포 폴더 대응 마스크 7개.
- `native/`: 마스크 41개. 정확한 3배 최근접 원본인 19개는 96×128 칸으로 복원했습니다. 나머지 22개는 손실 없는 축소본이 없어 현재 원본 픽셀 해상도를 보존했습니다. `manifest.json`의 `native_scale_to_game`이 각각 3 또는 1입니다.
- `previews/`: 각 `native/` 시트 전체의 4배 최근접 확대본 41개. 모든 프레임을 포함합니다.
- `manifest.json`: 원본 경로·해시, 마스크 경로·해시, 시트·칸 크기, 격자, 피벗, 프레임 순서, 프레임별 알파 경계·불투명 하단, 사용 재질 픽셀 수.
- `source_contact.png`, `material_contact.png`: 각 시트 첫 프레임의 원본·재질 구분 모음. 재질 모음은 구분을 보기 위한 색이며 실제 RG 데이터 색과 다릅니다.
- `validation.json`, `material_validation.json`, `review_validation.json`: 픽셀·대표 재질·브라우저 검증 기록.
- `review_desktop.png`, `review_mobile.png`: 검토 페이지 표시 확인용 캡처. Unity 캡처가 아닙니다.
- `inspect_sources.py`, `build_masks.py`, `validate_materials.py`, `validate_review.cjs`, `review_template.html`, `source_inventory.json`: 원본 조사·재생성·검증 자료.

## 원본 규격과 피벗 보존

이 작업 폴더의 모든 원본이 D-081 규격으로 교체된 상태는 아닙니다. 마스크의 최우선 조건인 **원본과 같은 크기·배치·알파**를 지키기 위해 기존 규격을 그대로 따랐습니다.

| 대상 | 칸 크기 | 피벗: 칸 왼쪽 위 기준 |
|---|---|---|
| D-081 캐릭터 19개 | 288×384 | (144, 360) |
| 주인공·마법사·오우거 기존 시트 | 256×384 | (128, 352) |
| 운반병 `crew_pull6`, `crew_push6` | 384×384 | (192, 352) |
| 설치 대포·포구 효과 | 256×256 | (128, 240) |
| 운반 대포 본체·포가 | 768×384 | (336, 352) |
| 별도 바퀴 | 101×101 | (50.5, 50.5) |
| 사다리 소품 | 256×1536 | (128, 1472) |
| 투사체 | 256×128 | (128, 64) |

행 우선, 각 행 왼쪽에서 오른쪽 순서입니다. 주인공 격자는 뒤 걷기·옆 걷기·옆 달리기·앞 걷기의 4행, 고블린 격자는 걷기·공격의 2행을 유지합니다. 나머지는 원본 순서를 유지합니다. 발을 새로 정렬하지 않았으며 쓰러짐·달리기 중 원본의 들린 발도 그대로입니다. 원본에 이미 있는 낮은 알파 픽셀도 보존했습니다. 새 불투명 픽셀이나 잔여 픽셀은 추가하지 않았습니다.

## 검토 페이지

상단에서 시트·동작 행·프레임을 선택하고 확산광과 확산광+반사광을 비교합니다. 동작과 빛 이동은 따로 멈출 수 있고, 빛 위치·강도·반사 배율을 조절할 수 있습니다. 하단 45개 동작 카드는 현재 원본과 마스크를 함께 재생합니다.

선형 색 공간에서 Blinn–Phong 반사를 계산합니다. 매끄러움에 따른 지수는 `2^(1+10G)`입니다. 원본 그림은 색으로, 마스크는 선형 데이터로 읽습니다. 검토 화면의 조명은 재질 구분 확인용이며 최종 Unity 화면과 동일한 조명 구현은 아닙니다.

K-081 출력 폴더는 현재 작업 폴더에 없습니다. 검토에서는 크기가 일치하는 기존 노멀맵 3개(`hero_walk_run_grid`, `ogre_static`, `wizard_back_static`)만 사용했습니다. 기존 노멀맵 5개는 현재 컬러 시트와 크기가 달라 사용하지 않았습니다. 나머지도 평면 법선 (0,0,1)로 표시하고, 각 시트에 이 상태를 명시했습니다. 법선을 추정하거나 노멀맵을 새로 만들지 않았습니다. K-081 통합 후에는 같은 크기의 새 노멀맵과 함께 실제 조명을 확인해야 합니다.

## 확인과 연결 시 주의

41개 파일의 크기·알파 바이트 일치, B=0, 완전 투명 픽셀의 RGB=0, 142프레임의 알파 경계·불투명 하단 일치, 정수 최근접 원본 왕복 일치, 전체 시트 4배 미리보기 크기를 검사했습니다. 피부·머리·옷·나무·총열·금장·철 버클의 대표 위치 15곳도 별도 검사했습니다. 이것은 모든 재질 픽셀의 의미를 사람이 수작업 검수했다는 뜻은 아닙니다.

브라우저에서는 내장 이미지 85개 로드, 41개 시트 선택과 142프레임 표시, 미리보기 알파 일치(광원 표시점 영역 제외), 반사 배율 0일 때 양쪽 화면 일치, 동작 재생, 모바일 가로 넘침 없음, 스크립트·요청 오류 없음도 확인했습니다. 데스크톱·모바일 캡처와 재질 구분 모음을 직접 열어 확인했습니다.

게임에 복사할 때 원본 컬러/노멀맵과 같은 이름 줄기에 `_spec`을 붙이면 됩니다. 예를 들어 `gunner_static.png`, `gunner_static_normal.png`, `gunner_static_spec.png`입니다. 사다리 운반 시트의 기존 노멀 이름만 `ladder_goblin_carry_normal.png`로 다르며, 마스크는 컬러 시트 이름인 `ladder_goblin_carry_run4_spec.png`를 따릅니다. K-081에 대응 결과가 없으므로 이번에는 본 출력 폴더 안에서 원본 상대 구조를 따랐습니다.

가져오기 설정은 **sRGB 끄기, Point, 압축 없음, 밉맵 끄기, Clamp, 일반 데이터 텍스처**를 권장합니다. 마스크를 노멀맵 형식으로 가져오면 안 됩니다. 셰이더가 G에서 매끄러움을 읽도록 연결해야 합니다. 원본 시트가 바뀌면 해시·배치·재질 영역을 확인하고 마스크를 다시 생성해야 합니다.

Game 폴더·기존 노멀맵·협업 기록을 수정하지 않았습니다. Unity 실행·실제 게임 조명 확인·셰이더 연결·Git 쓰기는 수행하지 않았으며 Claude의 통합 작업으로 남습니다.

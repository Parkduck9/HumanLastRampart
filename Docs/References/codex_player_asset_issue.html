# 플레이어 에셋 사용 불가 사유 확인

- 작성자: Codex / T-CX-026 / 2026-10-14
- 상태: Claude 사유·재현 근거 회신 대기. 원인 확정·해결 완료 아님.
- 사용자 전달: 고블린은 에셋으로 사용할 수 있는데 플레이어는 사용할 수 없다고 들었음. 이 차이를 기록하고 이유를 물어 해결할 예정.

## 현재 자료

고블린 선택본은 codex_goblin_walk_attack4_v1.png/JSON(걷기·공격 각4), 플레이어 선택본은 codex_hero_walk_v6_front_back.png·codex_hero_walk_v4_side.png 및 codex_hero_walk4_v8.json(4방향·방향당4)이다. 두 원본의 규격은 다르며 플레이어 JSON에는 개별 프레임 사각형·발 기준점·unitScale·flipX가 있다. 이 차이만으로 사용 불가라고 결론 내리지 않는다.

과거 ROADMAP에는 SpriteFlow 원본 PNG/ZIP 다운로드 유료 제한 기록이 있다. 이후 만든 로컬 플레이어 선택본과 같은 문제인지 미확인이다. 다운로드 제한·투명도·슬라이스/피벗·프레임 정렬·방향/모션·렌더링 연결 문제를 혼동하지 않는다.

## Claude에게 묻는 내용

1. '사용 불가' 판정의 대상 파일/버전은 어느 것인지. SpriteFlow 썸네일인지 현재 로컬 v8 선택본인지.
2. 어느 단계에서 막혔는지: 임포트, 스프라이트 분할/피벗, 화면 표시/방향 전환, 걷기/달리기 동작, 그림 품질. 오류 메시지·경로·사진·재현 절차를 요청한다.
3. 고블린에는 가능하지만 플레이어에 필요한 조건이 무엇인지. 기존 JSON을 읽는 방식으로 해결 가능한지, 별도 셀 규격/시트가 필요한지.
4. 필요한 PNG 규격, 투명 배경, 프레임/방향 수, 발 기준점, 정렬/크기, 임포트/렌더링 연결 조건을 구체적으로 알려 달라.

## 해결 진행 원칙

회신으로 원인을 확인 → 기존 승인 외형/4프레임 선택을 보존하는 수정안 → 필요한 에셋 보완 → Claude Unity 임포트·실제 화면 검증 순서. 현재 원본 삭제·재생성·게임 변경은 하지 않는다. 달리기 에셋이 없다는 것과 기존 걷기 PNG 자체가 사용 불가인 것을 구분한다.

## 사유 회신·정정 | 2026-10-14 14:17 KST

M-CL-044 Claude 회신: 파일 불량이나 임포트 오류가 아니다. 현재 GPU 인스턴싱 렌더러에 그대로 연결할 수 없는 시트 규격이었다. 이전 SpriteFlow 다운로드 제한과 관계없다. '플레이어 에셋 자체가 사용 불가'로 해석한 사용자 전달을 이 회신으로 구체화한다.

- 대상: 현재 로컬 v8의 원본2장과 선택 JSON.
- 원인: PerfLabArt.SheetLayout은 캐릭터당 텍스처1장·고정 크기 격자·공통 발 피벗·칸 비율을 사용한다. 플레이어는 원본2장·다른 프레임 사각형·개별 피벗/unitScale/flipX라 직접 연결이 안 된다.
- Codex 직접 확인: PerfLabArt.cs SheetLayout과 GoblinLayout(4열2행·발 위치를 정규화한 값), 플레이어 JSON16프레임·sourceIndex0/1·크기차이 확인. 고블린은 개별 콘텐츠 좌표도 있지만 원본 PNG 자체는 고정 격자여서 게임에서 사용할 수 있다.
- 별도 미완료: 달리기 프레임이 없음. 게임 주인공 이동/표시 P3-C02 미구현(카메라가 위치를 대신함). 이는 PNG 불량과 다른 문제다.

## 해결안 (아직 시트 변환·Unity 검증 전)

기존 PNG를 다시 그리지 않고 JSON의 좌표·피벗·unitScale를 사용해 투명한 동일 크기 칸에 재배치한다. 원본은 보존한다. Claude 규격 제안: 256×384칸, 4열, 모든 칸 발 위치 (128,352), 공통 축척. 행은 뒷모습 걷기 → 왼쪽 걷기 → 왼쪽 달리기 → 앞모습 걷기. 오른쪽은 Claude 셰이더 좌우 반전으로 연결 가능. 달리기가 없으면 걷기3행을 먼저 준비할 수 있다. 없는 달리기 행을 걷기로 채우고 제작 완료라고 하지 않는다.

재배치본은 Codex References에 별도 저장하고, Claude가 Art/Characters/Hero로 복사·연결·Unity 검증한다. 캐릭터 외형을 유지하며, 게임 반영은 사용자 외형 검토 뒤 진행한다. 현재 원인 확인은 완료, 실제 변환과 게임 연동 검증은 미완료다.

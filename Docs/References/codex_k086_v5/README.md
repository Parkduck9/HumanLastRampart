# T-CX-093 — 점화병 v5와 도화선 그림

사용자 “다음진행해”로 직전 제안한 뒤쪽 윗면(128,134) 점화 위치와 동작 제작을 진행했다. 144×128/발96,120 → 게임432×384/발288,360, 기준 인물73도트를 유지했다.

## 제작과 보존

- 동작 관련 내장 imagegen 3회: 전체6칸1회, 단독 접촉 포즈2회. 전체 생성 결과는 사각 광채 경계와 칸 겹침이 있어 최종 포장에 쓰지 않았다. 마지막 단독 포즈를4번으로 채택했다.
- 기존 v3의1·2·3·5칸을 RGBA 그대로 보존하고,6칸은1칸 복사로 순환을 닫았다. 새4번은 별도 생성 이미지의 약2배 머리폭 해상도를 정규화한 뒤 공통 배율로 축소·발 등록했다. 포즈별 전체높이를 늘이거나 색을 손그림으로 고치지 않았다. 이 정규화는 관절 리깅이나 모든 구간의 동일한 횃불 길이 검증을 뜻하지 않는다.
- 이전4번의 긴 자루 대신 팔·몸을 왼쪽으로 뻗는 자세를 쓴다. 보이는 자루 길이·자세·불꽃 크기에는 아직 생성 편차가 있다. 전체6칸의 물리적 횃불 길이가 정량적으로 완전히 같다는 주장은 하지 않는다.
- 대포 도화선은 별도 imagegen1회. 결과를256×256로 정규화하고 작은20×19px 영역만 기존 반동3칸의 뒤 덮개에 포장했다. 구역 밖 원본 픽셀과 전체 원본 알파를 유지한다. 기존 Game PNG·meta는 바꾸지 않았다.
- 프롬프트 원문과 생성 원본은 source/·PROMPTS_FULL.md, 포장 코드는 build_pack.py에 보존했다. 노멀맵은 만들거나 연결하지 않았으며 이전 점화 노멀을 혼용하지 않는다.

## 수행한 확인

`validation.json`: 정확nearest3배,6칸 발y120, 첫칸/끝칸 동일, 기존4칸 보존, 대포 구역 밖 RGB/전체 알파 보존 통과. 밝은4번 불꽃 경계는 native[7,54,19,69]이며, 같은 바닥선의2D 접점 고리(12.57,62.96)와 심지 끝(15.80,57.58)을 포함한다. 실제 카메라와는 구분한다.

내장 HTML에서 재생→6번 진행·4번 접촉칸 정지, 콘솔 오류/경고0을 실제 브라우저에서 확인하고 browser_review.png를 보관했다. 원본 대포/병사 PNG 전체를 바꾸지 않고 같은 바닥선 합성을 보여준다.

## 실제 카메라 결과 — 미완료 사항

`PlayProbe.IgniteContactSixFrames`는 v5 두 텍스처를 메모리에서만 로드하여 실제 A 전투 카메라의6칸을 각각 촬영했다. 첫 실행은 시험 메서드와 클래스 이름 충돌로 컴파일 실패,2번째는 공용 도우미가 준비 화면을 자동 시작해 실패했다. 완전한 클래스 경로와 KeepPreparation 복원 설정으로 고친 뒤3번째1/1 통과했다. 결과는 `../codex_ignite_camera_20261021/qa/attempt3/`다.

기술 시험은6칸·피벗·실제 동작 버퍼·임시 재질 연결·시간 정지·PNG생성 확인이다. 부모가 실제3/4/5번 사진을 읽었을 때 **불꽃이 도화선 고리보다 아래**에 보였다. 실제 접촉 성공·최종 동작 완성을 뜻하지 않는다. 원본2D 비교는 대포와 병사 발을 같은 바닥선에 두었지만 실제 배치는 대포가 병사보다 앞쪽이고 투영이 달라진다. 원인 수치와 최종 보정값은 아직 실증하지 않았다.

Game 그림 연결은 보류한다. 다음은 새 그림을 반복 생성하기보다 대포·운용병 앞뒤 위치, 셰이더 빌보드 보정과 접점 투영을 함께 측정해 바로잡는 작업이다. 이번 동작 생성3회를 마쳤으므로 더 생성하지 않았다. `Loop_Engineering_v1.md`의 “한 항목에3번까지 고쳐 보고, 넘으면 멈추고 보고” 원칙을 따른다.

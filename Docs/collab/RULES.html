원본과 사본

live 기록 보존

live는 Git으로 복원되지 않으므로 기록을 지우지 않고 맨 아래에만 추가합니다. 마일스톤 완료, 대체 전환, 복귀 시 현재 조정 담당이 자기 표시(_CL/_CX)가 붙은 새 폴더에 텍스트 사본과 BACKUP_INFO.md를 남기고 커밋합니다.

공용 경로(Core/, ProjectSettings/, Packages/, 빌드 씬 목록, 공통 UI, 공유 ScriptableObject)를 건드리려면 조정 담당의 예약 승인이 필요합니다. 씬과 프리팹은 담당자 한 명만 수정합니다.

6소통: "협업 확인" (수동 1단계)

AI가 메시지를 남겨도 상대는 자동으로 읽지 않습니다. 사용자가 "협업 확인"이라고 지시하면 아래 순서로 처리합니다.

규칙 다시 읽기
FirstRead → RULES → DECISIONS → CONTRACTS
상대 outbox 확인
자기 앞으로 온 새 메시지
예약·인계 기록 확인
현재 유효한 조정 담당(평상시 Claude, 대체 기간 Codex)의 tasks + 자기 tasks
한글로 보고
처리 결과, 막힌 점, 사용자에게 물을 것

메시지 규칙

  • 자기 outbox 맨 아래에만 추가
  • 회신은 자기 outbox에 원본 ID를 인용
  • ID에 작성자 접두사: T-CL-001, M-CX-003

반복 협의 제한

요청과 회신 한 쌍을 1회로 셉니다. 같은 주제로 3회 후에도 해결되지 않으면 그 작업만 보류하고 사용자에게 질문합니다.

이후 단계(현재 미적용): 2단계는 새 메시지 알림만(Discord 등), 3단계는 자동 실행. 전환은 사용자가 결정합니다.

10Git 규칙 (한 작업 폴더)

✓ 해야 하는 것

  • 둘 다 develop에서 작업, 브랜치 전환 금지
  • 자기 파일만, 파일 단위로 지정해서 커밋 (.meta 포함)
  • 커밋 메시지 첫 줄에 작업 ID
  • Git 쓰기는 조정 담당의 허가를 받은 뒤 한 번에 한 AI만

✕ 금지

  • git add ., 전체 커밋
  • 상대 스테이징 해제, 이력 재작성
  • main에 직접 커밋
  • index.lock 직접 삭제 (반복되면 사용자에게 알림)
  • 강제 옵션(--force, +), 변경 삭제(reset --hard, clean)

최초 develop 전환 (유일한 예외)

규칙 최종 확정→ 기존 변경 파일 확인·보고→ main 초기 커밋→ develop 생성→ Claude가 1회 전환→ 이후 전환 금지

변경 파일이 있으면 사용자 판단 전까지 전환하지 않습니다. 강제 전환과 변경 삭제는 하지 않습니다.

Git 쓰기 순서 (요청 → 허가 → 시작 → 종료)

단계누가어디에 기록
1. 요청 G-CX-004요청한 AI자기 tasks.md + 조정 담당에게 알림
2. 허가현재 조정 담당조정 담당 tasks.md (이전 허가 종료 확인 후에만)
3. 시작요청한 AI자기 tasks.md (허가 확인 후에만)
4. 종료요청한 AI자기 tasks.md (결과 커밋 또는 실패)

tasks 기록은 운영 기록이지 실제 잠금이 아닙니다. 순서는 조정 담당 한 명의 허가로 보장합니다. 종료 기록 없이 중단되면 종료를 추정하지 않고 사용자에게 보고합니다.

main 반영 절차

승인 요청 작성 — 묶음 ID, 커밋 X와 현재 main의 전체 SHA, 포함 커밋 전체 목록과 작업 ID
사용자가 커밋 X를 승인 — 이후 새 커밋이 생겨도 승인 대상은 X 그대로
Git 쓰기 허가 받기 — 위 요청 → 허가 순서
실행 직전 확인 — main이 승인 때와 같은지, X가 develop에 있는지, main이 X의 조상인지. 하나라도 다르면 중단
main 참조만 X로 이동 — 강제 옵션 없이, 앞 명령 성공 시에만. 작업 폴더는 develop 그대로
실행 후 확인과 기록 — main = X, 현재 브랜치 = develop. 로컬 반영이며 GitHub 게시가 아님

11실행 확인과 검증 구간

Play 확인과 실제 캡처는 사용자가 직접 합니다. AI는 확인 절차를 아래 형식으로 드립니다.

- 확인 대상 커밋: def5678
- 열 씬: Game/Assets/_Project/Scenes/Battle.unity
- 순서: Play → 스페이스바로 웨이브 시작 → 적이 성벽까지 이동하는지 확인
- 기대 결과: 적 2종 등장, 콘솔 에러 0
- 캡처 요청: C:\Unity\1\HumanLastRampart\Docs\collab\live\review\claude_T-CL-003_wave.png

검증 구간

"검증 시작" (대상 X)→ 두 AI: 정리 후 Game/ 수정 중단 기록→ 조정 담당: 양쪽 중단 확인 + Game/ 내용 = X 확인→ "검증 준비 완료" 안내→ 사용자 Play·캡처→ "검증 끝"

"미커밋 변경 없음"만으로는 부족합니다. X 이후에 커밋이 더 있으면 Play는 그 커밋을 실행하기 때문에, 현재 Game/ 내용이 X와 같은지까지 확인합니다. 다르면 reset이나 전환으로 맞추지 않고 보고합니다.

12완료 기준

작업 상태

제안→ 승인→ 진행중→ 구현 완료→ 통합 대기→ 사용자 검토 대기→ 완료 ·보류

작업 완료 = 그 작업이 포함된 커밋 묶음이 승인되어 main에 반영되고, 사용자 Play 확인까지 끝난 상태

첫 마일스톤 "1회차 완주" (에디터 Play 한 번으로)

0 메인→ 5 스토리→ 1·2 전투→ 4 보상·손실→ 3 정비→ 다음 전투 진입
  • 콘솔 에러 0, 각 화면의 실제 캡처를 사용자가 확인
  • 최소 기능만: 적 1~2종, 무기 1~2종, 스토리 대사 몇 줄, 상점 품목 1~2개
  • 빌드 실행은 다음 마일스톤
